# ERP 云备份：授权、恢复与迁移

ERP 创建、加密、调度和校验备份；OpenList 仅连接网盘和传输文件。不需要 fnOS 挂载或厂商桌面客户端。每天北京时间 03:00 创建本地完整备份；安装器保留该任务和其他 cron 配置，另加每两分钟检查队列。现有安装器仍要求主机 UTC+08:00，不改变本地备份时间语义。

## 私有连接器（可选，需运维明确执行）

模板 `infra/cloud-backup/compose.yaml` 固定 `openlistteam/openlist:v4.2.6`，仅绑定 `127.0.0.1:5244`；不加入 ERP compose，不自动安装、不自动授权，也不暴露管理端口或 Docker socket。官方镜像与数据目录依据 [Docker 安装文档](https://doc.oplist.org/guide/installation/docker)；版本依据 [官方文档版本](https://doc.oplist.org/) 和 [官方镜像标签](https://hub.docker.com/r/openlistteam/openlist/tags)。升级需主动复核驱动兼容性，不能使用浮动 latest。

在服务器专用目录放置模板，创建 `data`，权限设为 0700、归属 UID/GID 1001，然后由运维执行 `docker compose up -d`。管理界面通过 SSH 本地端口转发访问回环地址，不向公网发布。首次管理员凭据只在受保护的服务器终端查看，立即修改；不要贴进聊天、命令参数、仓库或工单。OpenList 数据包含厂商令牌，按机密保存。

用户必须按各厂商支持方式及所选连接器驱动的适用流程，分别完成百度、115、夸克的登录/授权；夸克历史逆向驱动不属于官方 API，不能将其流程称为官方授权接口。未授权的目标不会工作。为每个目标建独立的专用目录，例如 `/baidu/erp-backups`、`/115/erp-backups`、`/quark/erp-backups`。在 OpenList 创建仅能读写该目录的专用 WebDAV 账号，关闭游客及无关目录访问；ERP 使用此账号，不使用连接器管理员账号。实际权限应检查 PUT/GET/MKCOL 和仅限自身探测文件的 DELETE，不能只检查列目录。

每个挂载将 **WebDAV 策略**设为 **本机代理 / Native proxy**，直接返回文件内容，不能用 302 或代理 URL 重定向；参见 [官方存储通用设置](https://doc.oplist.org/guide/drivers/common)。ERP 拒绝重定向。配置由主机运维管理，默认 `http://127.0.0.1:5244`；网页不能任意修改连接器网络地址。自定义私有 origin 使用安装器 `--connector-url`，重新安装默认保留现有值。

夸克是实验性目标：[官方说明](https://doc.oplist.org/guide/drivers/quark)指出其历史逆向接口不会主动维护。只读/TV 驱动不能满足备份写入要求。不能保证授权、上传或长期可用；必须以实际写入、完整回读和恢复校验结果为准。

## ERP 配置与判定

### ERP 专用受管实例与扫码运行器

常规部署通过发布源中的 `scripts/erp-backup-install.py` 安装每日 03:00、每两分钟复制和新增的每分钟授权任务。未登记连接器时配置为 `connector_management=pending`；这只是可部署的待配置状态，不具备扫码能力，也不会安装、升级或接管已有外置 OpenList。授权 wrapper 每次检查 `.active-release`、`.deployment-state` 和发布路径范围，启动运行器前释放部署共享锁；运行器在每次操作重新取锁和读取当前发布。运行器的 55 秒截止只停止新 claim，已领取的有界网络操作继续完成和 checkpoint；wrapper 不再用竞争的 60 秒超时杀死它。独占 runner 锁防止下一分钟任务重叠。

仅经运维明确批准后，才能通过当前已验证发布源的安装器创建新专用实例：

```sh
python3 "$ERP_RELEASE/scripts/erp-cloud-connector-install.py" \
  --app-dir "$ERP_APP_DIR" --project "$ERP_PROJECT" \
  --mode create --connector-id CONNECTOR_UUID
```

`CONNECTOR_UUID` 为此次明确登记的新 UUID，不是密码。安装器仅在专用目录和同名容器都不存在时创建；缺少镜像时，只在显式 create 模式拉取固定 4.2.6，并记录实际不可变镜像 ID。不会接管占用相同回环端口的其他软件。管理员随机凭据写入 `APP/cloud-connector/admin-secret`（0600），只通过私有文件和标准输入使用，不能从网页或命令参数输入。引导环境文件及时删除，连接器日志关闭；Docker 管理权限仍可以读取容器私有环境，必须仅给可信运维人员。注册前实际验证管理员凭据。失败不更改已有实例；此次新建的私有目录可留给运维检查，不可误认为可用实例。

已有明确 ERP 专用的实例可以使用 `--mode managed --connector-id UUID --admin-secret-file APP/cloud-connector/admin-secret` 登记；要求固定版本、固定回环绑定、专用目录，以及匹配的 `erp.cloud.connector` 和 `erp.cloud.dedicated=true` 标签。不能把任意旧手动实例直接转换为受管实例。登记文件 `APP/cloud-connector/registry.json` 为 0600，数据目录为 0700，重装保留登记及原 daily/two-minute cron、origin 和恢复密钥设置。实际创建后再运行常规定时安装器以刷新 managed 状态。

安装、登记和恢复都不等于厂商开放条件通过。百度和 115 必须按所选模式分别完成真实授权、写入回读、刷新后再次上传及完整加密备份恢复，之前保持待验证；夸克仍为实验性手动配置。

### 免填应用信息：首次外部授权后导入

超管在“运维监控 → 云端加密备份”为百度或 115 新建绑定时，可使用 `openlist_builtin_import`，不需要申请或填写自己的 AppKey/AppID。现有自有应用扫码与手动 WebDAV 不会被此默认入口转换或自动替换。

1. 阅读并确认第三方授权说明，点击“打开授权页面”，在新标签页进入固定的 `https://api.oplist.org/`。选择对应网盘及使用 OpenList 提供的参数；网盘密码只输入在厂商登录页面。ERP 不嵌入该页面，不接收其自动回调，也不显示假二维码。
2. 按外部页面实际提供的流程授权，回到 ERP 将同一次新授权的 Access Token、Refresh Token 分别粘贴到遮蔽输入框，再点击“验证授权”。不要粘贴整个网页、回调地址、Cookie、UID、AppKey 或截图，不要把令牌发到聊天或工单。两项最多各 4096 字符；首次绑定完成后不必每次备份重复填写。
3. 验证任务先核对厂商账号身份，再执行一次受保护的刷新并核对新令牌身份。百度内置刷新不报告有效期时显示“到期时间未知”，不等于长期有效；115 必须取得有效期限。导入会话为 10 分钟，验证成功后另有 10 分钟配置期限，刷新页面不会延长。
4. 核对账号、选择专用目录，完成随机文件上传和完整读回，再明确确认“使用此账号与目录”。此确认之前原目标保持不变。验证或切换成功仍不代表已有可恢复云备份。
5. 百度、115 分别通过真实上传、完整回读、跨刷新后的再次上传、完整加密备份回读及隔离恢复，才开放其自动复制。未验收时保持自动复制关闭，本地备份照常运行。

这是“外部授权后首次导入”，不是 ERP 内纯扫码自动回传。OpenList 公共授权服务会处理网盘授权凭据；百度内置方式的后续续期也依赖其在线服务。若不接受此信任关系，使用高级设置中的自有开发者应用。重新授权可能受到厂商次数限制，或影响同一刷新链的旧授权；请使用新取得、未被其他挂载消费的结果，禁止从正在使用的 storage 抽出旧凭据再导入。

切换标签页不会清空当前有效登录会话的输入；确认服务端接收后清空令牌。关闭弹窗、退出或登录会话改变会清除输入。提交响应丢失时只查询原操作，不自动创建第二次验证；若提示“续期结果未确认”，不要反复提交旧刷新令牌，应重新取得授权结果。刷新凭据一旦交付连接器，后续续期仅由对应 storage 负责，ERP 不再重复刷新或写回导入时的旧值。

绑定入口要求实际超级管理员角色及全局运维权限。无 AppKey 不阻止导入，但受管连接器登记、运行器在线与维护检查仍必须通过。夸克不提供此导入入口。

### 自有应用与手动 WebDAV

自有应用设置中的百度 `client_id` 对应 **AppKey / API Key，不是数字 AppID**；`client_secret` 对应 **Secret Key / AppSecret**。115 的字段为 AppID / Client ID，PKCE 流程不要求 AppSecret。百度字段含义已于 2026-10-06 对照[官方设备码 SDK](https://github.com/baidu-netdisk/baidu-drive-sdk-go/blob/main/baidudriver/api/auth_device_code.go)和[官方 OAuth 参数说明](https://openauth.baidu.com/doc/doc.html)核对；不要把开发者平台显示的不同标识混填。

超级管理员在运维备份页填写上述逻辑路径和专用 WebDAV 凭据，保存后执行写入/回读连接测试，通过后再启用。密码为空代表保留原密码。连接测试成功只说明当前目录可以写读，不表示已有可恢复备份。更改配置后需重新测试。

云端每个备份版本只包含 `archive.tar.gz.enc` 和最后发布的 `complete.json`。完整加密包回读通过认证校验后才发布完成标记，不能把只有包或仅有标记的目录当成成功。失败目标彼此独立；无云账号授权或未完成回读时，不能宣称云备份已生效。大文件恢复仍需用户授权后单独演练。

不自动删除远程历史版本，需运维手动管理保留策略；清理前保留至少一份经过恢复演练的版本。远程目录不要存放明文、临时文件或恢复密钥。

## 密钥、灾难恢复与换服务器

备份主密钥（`--key-file`）与网盘备份分开保存，至少一份离线受保护副本；该主密钥刻意不包含在备份中，也不上传网盘，是解密完整备份的启动前提，不能靠备份本身找回。不要将它与应用字段加密密钥 `FIELD_ENCRYPTION_MASTER_KEY` 混淆：现有完整加密归档包含应用字段密钥及配置，拿到独立备份主密钥并通过认证解密后，可以从归档恢复它们。迁移旧数据库时仍须恢复对应的应用字段密钥才能解密已保存连接器凭据；若应用字段密钥与可恢复归档都丢失，则需重新授权/录入。

恢复先把一个版本的两个文件下载到隔离、本机受保护的 `BACKUPS/ID` 目录，使用现有 `scripts/erp-backup.py verify --app-dir APP --project PROJECT --backup-dir BACKUPS --backup-id ID --status-file STATUS --key-file KEY` 做认证及隔离恢复校验（APP 为已部署 ERP 根目录，STATUS 为受保护的独立验证状态文件）；`extract` 配合新的 `--recovery-dir` 仅导出到新目录，不对生产实例原地覆盖。继续遵循现有完整备份恢复流程，检查数据库、附件和镜像后再计划切换。不要绕过认证解密，也不要在生产数据库上试恢复。

迁移时带走经过校验的本地备份、单独恢复密钥、受保护的连接器数据与必要 ERP 凭据加密配置；新服务器重新部署 ERP 和连接器，检查目录归属/可用空间。使用安装器重新写入新 `app_dir`、compose project、backup/status/key 路径；它保留 secondary 配置与已有连接器 origin，迁移时应显式更新旧绝对路径。配置指向新服务器回环连接器后，重新执行三个目标连接测试及最新备份回读。换服务器不依赖 NAS 厂商挂载；实际云授权和完整恢复验证是切换验收条件。

受管连接器恢复子树位于加密包内 `recovery/cloud-connector/`，含冷数据、受保护的管理员/候选凭据、不可变镜像 ID 和非机密引用清单；不单独上传该目录。数据库导出快照同时记录候选挂载和用户 ID，不以安装器初始的空 objects 清单代替实际 ERP 引用。过渡性准备/清理记录仍保留用于恢复续作，但只要求完整 configured/verified/active 引用物理可恢复。

受管数据库快照会保留当时的维护 gate；源主机释放 gate 不会改变已导出的数据库。新主机顺序必须是：还原数据库及原 ERP 字段密钥 → 从同一认证备份还原连接器数据/管理员 secret 并以同一 connector UUID 登记专用实例 → 显式执行 `erp-backup.py recover-connector` → 验证业务/候选权限/新备份后再验收。具体命令和前提见 [完整恢复文档](encrypted-backup-recovery.md#新主机受管连接器维护-gate-交接)。交接认证原始加密归档，持久化恢复专用意图，并在释放 exact fence 的同一事务中关闭未完成的内置导入、要求重新授权；不恢复数据库、不创建实例、不切换流量、不自动启用任何云目标。已应用目标及受保护候选清理日志保留；租约过期或任意 JSON 不能作为清除依据。

授权来源、来源修订与日志协议版本随原记录恢复，不使用新页面默认值推断。升级至 `0064_cloud_auth_builtin_import` 保留旧 `own_app` 密文；已有新协议授权记录时不允许直接降级，避免旧程序误读凭据。同库进程重启时，已发送、未确认刷新不能重发旧令牌，已持久化的新令牌仅继续身份核对或候选交接。完整备份恢复不能证明这些令牌未在备份后被消耗，因此所有未完成内置导入均关闭并重新授权，不交付快照内旧令牌。参见完整恢复文档中的授权刷新状态说明。
