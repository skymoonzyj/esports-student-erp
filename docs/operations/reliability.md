# 结算、备份与运维可靠性

相关数据库迁移为 `0051_settlement_idempotency`、`0052_operations_history` 和 `0053_revenue_share_processing`。

2026-09-11 缺陷修复新增 `0055_manual_payment_idempotency` 和 `0056_evaluation_upload_cleanup`。前者增加人工收退款操作标识，后者保存评价暂存文件清理任务；两项升级不改写历史收退款金额。

## 人工收款与退款

收款、退款弹窗每次打开时生成操作标识。网络失败后保持弹窗和原内容再次提交，会返回已完成的同一笔记录；并发提交也不会重复记账或审计。同一操作标识更换金额、时间、对象等内容会返回明确的冲突提示。需要重新录入不同内容时，应先确认是否已有成功记录，再关闭并重新打开弹窗。

升级前已打开的旧页面缺少操作标识时会提示刷新页面并核对记录。刷新或关闭后重新打开弹窗属于新操作，无法替代财务对实际收退款凭证的核对。

固定分成额度按收入和退款扣减的净额计算，支持全退后重新付款。退款分成按实际已入账扣减金额计算本次差额，补录更早日期和同日退款不会因顺序变化多扣一分钱。已有历史账目保持原样，如需更正，应由财务核对后执行明确的调整。

## 结算登记

打开登记表时生成一次操作编号。请求超时或断网后，保持原内容重试，服务端返回原登记记录，不会再次增加已结算金额或重复写审计。

同一个操作编号提交不同内容会被拒绝。收款对象相同、打款凭证号相同的另一笔登记也会被拒绝，凭证号比较时忽略空白和英文字母大小写。请填写银行或支付渠道实际凭证号，不要反复使用“现金”“已付款”等通用文字。

历史记录及其金额不变；迁移会为已有凭证预留去重标识。既有重复记录需要财务核对，不会自动删除或调整。

## 分成查询与增量重算

“我的分成”按本人过滤后汇总余额，流水支持每页 20/50/100 条。分页使用日期和流水编号定位，继续读取下一页时不跳过越来越多的历史行；同一时刻的多条流水也有稳定顺序。分页不会把累计余额变成当前页小计。

新付款和新退款通过数据库触发器在同一个事务进入待处理清单，退款补录过去日期也不会漏掉。现有收款、退款、确认入班仍执行原来的同步分成逻辑；有收益流水且已核对退款的付款会移出清单。尚未满足条件、以及暂时没有任何收益流水的付款会保留，补齐规则、教练或邀请绑定后可再次处理。已有收益流水继续沿用原规则快照，不追溯改写。

管理端一次点击按每批 50 笔请求处理（接口上限 100），每笔付款和该笔重算审计独立提交。界面显示累计进度，支持暂停、继续及失败重试；关闭页面会停止发送后续批次，已经提交的结果会保留。当前批次内遇到失败时，此前成功的付款也不会回滚。新入队记录留待下一轮，使用数据库时间确定边界，避免服务器之间的时间差影响遍历。

独立重算按营期、入班记录、报名、付款的既定顺序加锁，并在关系变化时回滚该笔后重试。单笔等待锁超过 3 秒会给出中文繁忙提示，可以稍后继续，不会长时间等待整个付款清单。

`0053` 仅创建调度清单、索引及触发器，并回填历史候选。它不会自动重写历史账目；回填有退款的付款进行一次补偿核验后，正常已完成记录不再参与后续重算。

## 自动备份与恢复

NAS 部署脚本会安装北京时间每天 03:00 的备份任务，并在本次发布后立即运行一次加密备份和隔离恢复验证。具体备份路径、独立密钥保存、保留周期和恢复步骤见 [加密备份与恢复说明](encrypted-backup-recovery.md)。

恢复验证使用没有对外端口的临时数据库，不覆盖当前业务数据。只有加密文件完整性、数据库恢复、结构及行数、敏感数据解密和评价媒体校验通过，才记录验证成功。

后台运维页面显示备份最近执行结果、最近成功时间、大小、恢复验证时间与自动复制副本状态。未配置独立存储设备时会明确提示；同一 NAS 内的备份不能替代独立设备副本。

## 运维历史与告警

仅超级管理员且拥有运维查看权限可以访问历史、备份状态和告警。确认告警需要有效会话及 CSRF 校验，并记录中文安全审计。确认仅表示已知晓，不代表问题恢复。

请求量以分钟为单位持久化，默认保存 30 天。每 15 秒批量写入，各 API 进程共同汇总；提交重试使用批次标识去重。正常停机尝试完成最后一次写入，突然断电或强制终止仍可能丢失尚未写入的短时间缓冲，数据库故障期间窗口可能更长。P50/P95/P99 使用分段直方图估算。

页面支持近 1/7/30 天历史分页，当前异常、已恢复和全部告警筛选。历史从功能启用时开始，不补造过去数据。

后台每分钟检测服务端错误、调度器心跳、评价失败任务、备份与恢复验证、磁盘空间等状态；证书会定期检查。连续异常合并为同一事件，恢复后关闭，再次异常产生新事件。缺失探针数据不会直接把既有故障标为恢复。

这些告警在 ERP 内展示；尚未配置站外邮件或短信通知。监控与 API 同机运行，整机离线时无法向站外发出通知，需要另外的外部可用性监控才能覆盖该场景。

可通过环境变量调整采集间隔和保留天数：`OPERATIONS_FLUSH_INTERVAL_SECONDS`、`OPERATIONS_MONITOR_INTERVAL_SECONDS`、`OPERATIONS_RETENTION_DAYS`。备份状态文件以只读方式挂载，API 无权读取备份解密密钥。

## 评价上传暂存清理

教学调度器每轮在营期处理之后，全局检查过期上传；默认每 30 秒运行，每批最多处理 50 个过期会话。用户不再登录、切换项目或账号停用，也不影响过期清理。

替换、删除、取消、任务提交和过期处理，会在业务事务中保存暂存文件清理任务。只有业务事务提交后才删除文件；删除失败会保存重试次数并延后重试，进程重启不会丢失任务。仍有失败重试时，调度器心跳会报告异常，恢复后自动清除异常状态。API 与调度器必须挂载相同的评价媒体和暂存卷。

同时有效的上传会话默认每个账号最多 5 个、全系统最多 500 个，每个会话仍保留原有文件数量、单文件大小和 30 分钟有效期限制。超额时返回中文提示，可通过 `EVALUATION_UPLOAD_MAX_OPEN_SESSIONS_PER_ACCOUNT` 和 `EVALUATION_UPLOAD_MAX_OPEN_SESSIONS_TOTAL` 调整。过期会话不占有效会话配额。

`0056` 回退会拒绝丢弃尚未完成的清理任务，应先恢复文件系统并等待任务排空。没有数据库关联的既有孤立文件不自动批量删除。
