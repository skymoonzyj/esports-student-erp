# 天赋评测 2 开发裁决记录

日期：2026-09-22

## 文档性质与来源

本文是“天赋评测 2”开发期间的裁决记录，用于解释实现边界、选择理由和已接受的代价／权衡。裁决按内部进度账本 `.superpowers/sdd/2026-09-21-talent-assessment-2/progress.md` 中 `Ruling:` 的出现顺序整理，共 41 条。

文中的 `Task*`、`agent*`、内部路径、提交候选及评审席位均为开发协调标识，仅用于追溯裁决上下文。它们不表示对应实现、测试、浏览器验收、真机验收、发布或部署已经完成。

本文尤其不构成以下证据：

- NAS 已部署或线上发布成功；
- 完整后端／前端测试已经通过；
- Windows、macOS、Safari、Chrome 或 Edge 已完成真实环境验收；
- iPhone Safari 或 Android Chrome 已完成真机验收；
- 任何套系已经开放。

实际可用范围必须以最终验证记录、设备验收记录、发布清单和部署回执为准。

## 裁决

1. **隔离工作树与发布快照**
   - 决定：使用携带当前发布源精确快照的原生隔离工作树，不只基于陈旧 `HEAD`。
   - 原因：发布目录包含大量已部署但未提交的工作。
   - 代价／权衡：增加本地磁盘和一个私有快照提交；不改源代码，最终集成前必须对比清单再应用本功能差异。

2. **并行子任务方法**
   - 决定：按用户批准的独立文件所有者并行方式执行，覆盖 SDD 通用的串行实现建议。
   - 原因：用户有明确偏好，计划依赖图也允许并行。
   - 代价／权衡：增加协调成本；契约必须先评审通过，数据库测试仍须串行。

3. **无真机证据时关闭手游套系**
   - 决定：可以完成手游代码与模拟回归，但缺少真实手机证据时保持手游套系关闭。
   - 原因：批准的规格明确区分模拟回归与真实设备验收。
   - 代价／权衡：手游开放时间延后，但绝不形成虚假的“全部交付”声明。

4. **练习难度的距离倍率**
   - 决定：练习目标距离倍率也应用于移动射击与节奏玩法的检查点距离；玩家速度和容差保持固定。
   - 原因：这些是对应场景中与距离直接相关的参数。
   - 代价／权衡：若试用反馈需要不同曲线，未来须做版本化调参；正式难度 3 不变。

5. **权限默认授权写入迁移**
   - 决定：新迁移除 RBAC 目录外，还要幂等写入新权限及默认授权。
   - 原因：`deploy-nas` 不会另跑 seed，且既有 0058 迁移采用同一模式。
   - 代价／权衡：增加升级／降级测试；避免权限只在全新测试库存在。

6. **不可变报告与比较组装**
   - 决定：报告生成保持纯函数并由调用方传入 `report_id` 和比较结果；生命周期层在原子持久化前计算真实前序比较或无历史条目。
   - 原因：不可变报告不能在后续读取时变化。
   - 代价／权衡：需要显式服务组装和跨层测试。

7. **补充读取尝试详情接口**
   - 决定：加入 `assessmentApi.readAttempt`，对应 `GET /attempts/{id}`。
   - 原因：缓存丢失后的对账需要服务器权威保存状态；Task7 示例方法清单遗漏了该规格要求。
   - 代价／权衡：增加一个客户端端点和回归测试，不扩展业务范围。

8. **Task8 与 Task7 并行**
   - 决定：Task1 评审通过后，Task8 可与 Task7 并行。
   - 原因：纯时钟、输入、布局和设置不依赖客户端缓存实现。
   - 代价／权衡：后续需要集成核对，但不允许契约分叉。

9. **固定时钟边界**
   - 决定：时钟输出 `n*1000/120`、`n=1..7200` 的模拟边界，最后为 60000；只有输入时间戳使用排他的 60000 上界。
   - 原因：必须完整积分最后一个区间，同时忽略迟到输入。
   - 代价／权衡：需要明确的结束边界引擎测试。

10. **技能取消动作**
    - 决定：内部 skill `InputAction` 增加可选 `cancel`；`cancel=true` 隐含 `release=false`。
    - 原因：`pointercancel` 必须清除已蓄势技能且不能发射，也不能与普通瞄准混淆。
    - 代价／权衡：增加一个内部字段和取消回归，传输格式不变。

11. **补充 HTTP DTO 的归属**
    - 决定：补充 DTO 放在前端 `apiContracts.ts` 和后端 `query_schemas.py`，不重新打开 Task1 核心契约所有权。
    - 原因：上下文需携带本人进行中轮次，正式历史按轮次呈现，尝试详情需返回已保存结果供缓存丢失恢复。
    - 代价／权衡：增加镜像 schema 测试与跨任务集成，同时保持已评审核心稳定。

12. **工厂必须接收视口**
    - 决定：`GameFactory.create` 增加必填第四参数 `viewport: Size`。
    - 原因：FPS 目标必须依据真实宽高比保持物理可见、可达。
    - 代价／权衡：需更新工厂／Host 和极端宽高比可行性测试；接口格式不变。

13. **精准定位的目标参考系**
    - 决定：目标可见性以“前一个目标中心”的设计参考和真实视口计算，保留玩家当前相机及精确种子角步进。
    - 原因：玩家转开后不能瞬移目标或重置视角。
    - 代价／权衡：需要记录参考系并覆盖边缘、俯仰和距离测试。

14. **复用空闲独立评审席**
    - 决定：协作工具因线程上限拒绝新评审者时，复用空闲的独立评审席。
    - 原因：避免停工或由实现者自审。
    - 代价／权衡：可能带入既有上下文偏差；以全新的精确 brief／package 和排除无关旧发现缓解。

15. **评分保持精确有理数**
    - 决定：直到最终 half-up 判定都保持精确有理数，不采用计划中的中间 Decimal 比率舍入。
    - 原因：已确认合法的 5.5 边界被中间舍入成 5。
    - 代价／权衡：需要小幅内部算术修改和边界测试；公式与接口指标不变。

16. **新运行时目录改名**
    - 决定：仅把新模块的 `runtime` 源目录改为 `engineRuntime`，撤销临时 `.gitignore` 例外。
    - 原因：主部署脚本会在快照和上传时排除所有 `runtime` 目录。
    - 代价／权衡：更新新模块导入与计划路径；既有运行时数据排除策略保持不变。

17. **重放时的服务器时间与撤回套系**
    - 决定：授权的尝试重放只刷新响应中的 `server_now`，保留已存身份、种子和截止时间；撤回套系禁止新尝试，但允许成功重放和有效既有尝试提交。
    - 原因：租约计算需使用当前服务器时间，已完成工作仍必须可恢复。
    - 代价／权衡：增加 availability／replay 测试，不改变存储中的尝试。

18. **精确 pending 删除与预览配置**
    - 决定：Task15 增加按完整身份和 operation 匹配的 `removePending`；`previewTaskConfig` 必须基于 `contracts.ts` 已登记参数和严格 schema。
    - 原因：一条保存结果不能清除无关 pending；练习分配前试练需要所选难度配置，且不能新增 HTTP 路由或复制公式。
    - 代价／权衡：窄幅扩展已评审缓存／契约并增加回归；预览配置永不权威，真实运行必须使用服务器 `AttemptView` 的配置和种子。

19. **移动射击场景几何**
    - 决定：检查点侧向使用轮次开始 yaw 冻结的水平右向量；目标位于开始 yaw、pitch 0 的眼位前方 10 米并在本轮固定；相机相对摇杆移动归一化，目录距离倍率只应用一次；增加非交互、由场景推导的检查点方向／距离提示。
    - 原因：批准配置没有额外角距离分箱，不应发明瞄准难度曲线；侧向地面标记可能不在前方视野内。
    - 代价／权衡：协调场景刻意保持简单；若未来调位需升级引擎版本。

20. **小地图显式可见状态**
    - 决定：在 Task12 修复中加入内部 `MobaSceneSnapshot.minimap.visible`。
    - 原因：真实小地图事件之间 `event=null`，不能据此判断面板是否显示。
    - 代价／权衡：窄幅更新运行时类型／fixture 并做下游编译检查；传输格式和世界几何不变，Host 仅在 visible 时保留地图控制排除区。

21. **跟踪覆盖与计数采样**
    - 决定：覆盖时长按每个带时间戳输入因果积分；描述性的丢失／重新捕获计数每个 120Hz 桶最多记录第一次丢失。
    - 原因：高频事件不能追溯性赚取整 tick，也不能让有界原始计数溢出。
    - 代价／权衡：Task16 需解释计数采样；覆盖率和评分仍基于真实时长。

22. **补刀小兵位置**
    - 决定：补刀小兵采用玩家附近固定偏移，并在世界范围内调整以保持独立且处于攻击范围。
    - 原因：规格将其定义为时机任务，并要求小兵始终可达。
    - 代价／权衡：呈现更简化，留待 Task18 检查；移动仍取消前摇，冻结的血量／窗口时序不变。

23. **不可比较报告的事实理由**
    - 决定：Task16 在没有干净可比基线时，为不可变比较写入事实性的配置、设置、环境及前序质量差异。
    - 原因：规格要求并列展示不兼容结果及原因，泛化的“无历史”不足。
    - 代价／权衡：Task5／6 后需窄幅扩展 formal service／query／test 所有权，并让 UI 授权读取前序报告；既有“最新干净可比”SQL 仍优先，不兼容或当前有警告时不算 delta。

24. **练习原始指标比较范围**
    - 决定：只比较当前已加载页中用户明确选择的两条练习，且套系、项目、难度、配置、设置、环境完全一致并无质量警告。
    - 原因：规格只允许可比原始差异，不要求自动扫描全历史练习基线。
    - 代价／权衡：限制为同页选择；不新增路由、全历史读取、评分、等级或进度百分比。

25. **过期中断返回 410**
    - 决定：Task6 对正式与练习都把“中断时已过期”的服务结果映射为 `AssessmentExpired410`，而不是成功 `200 expired`。
    - 原因：冻结客户端的中断成功只接受 `interrupted`，过期运行也无法再被有意义地中断。
    - 代价／权衡：增加路由测试和 Task15 过期对账；服务内部终态投影不变。

26. **前端并行启动边界**
    - 决定：Task15 可基于已评审 Task7 HTTP 契约先行，Task16 UI 也可在明确文件边界下并行；Task6 同时实现冻结端点。
    - 原因：剩余依赖是运行时验收，不是缺少客户端接口。
    - 代价／权衡：需要后续集成验证；Task6 评审前两者不能声称真实 HTTP 完成，Task16 后端仍受 Task6 query 所有权和 DB 租约阻塞。

27. **授权报告列表入口**
    - 决定：授权报告列表放在 `history?view=reports`，不增加第四个独立报告列表页。
    - 原因：冻结的 reports API 与筛选适合既有记录界面。
    - 代价／权衡：增加一个 URL view 选择器；报告详情仍为 `reports/:reportId`，本人正式／练习模式保持分离。

28. **浏览器能力证据模式**
    - 决定：桌面、触屏、WebKit 使用独立精确证据模式：桌面包含一次真实 Pointer Lock 丢失导致的 `pc-fps` 练习中断；触屏包含一次真实旋转导致的 `mobile-fps` 练习中断；WebKit 只到 trial 且零评测行。
    - 原因：原先“全部为零”的能力模式与运行时中断用例冲突。
    - 代价／权衡：增加多个 verifier mode；仍保持零结果／报告／audit 的严格检查和主流程 8／2／2 计数。

29. **Task17 提前编写集成／并发测试**
    - 决定：允许 Task17 在 Task16 后端完成前，针对冻结 HTTP／service 契约编写隔离测试，但不能运行 DB 或修改共享隐私／服务代码。
    - 原因：测试编写独立于剩余日期／比较逻辑。
    - 代价／权衡：后续可能需调整，并须在独占租约下完成真实 RED／GREEN；不减免任何验收门禁。

30. **帧间隔按窗口重叠计时**
    - 决定：Task15 可为 `FrameQualityTracker.recordFrameGap` 增加可选 `observedDurationMs`，默认仍等于真实 gap；max 和 `>500ms` 中断继续使用真实 gap，只有 `>50ms` 长帧累计使用运行窗口内重叠，并校验有限且 `0<=observed<=gap`。
    - 原因：最后一个 RAF 区间可能跨过 60000，否则会高估窗口内长帧时长。
    - 代价／权衡：窄幅扩展共享质量接口和测试，并增加 Host 首／末帧回归；DTO／raw 不变，也不通过钳制掩盖重复计数。

31. **Task18 浏览器用例拆分所有权**
    - 决定：浏览器 authoring 按独立所有权拆分并与 seed 工作重叠：`/root/ea_task9_fps` 先提共享 helper 并负责 PC／recovery，`/root/ea_task7_client` 负责 seed／verifier／touch／capabilities／runner。
    - 原因：这些文件可独立推进。
    - 代价／权衡：需要明确 helper handoff 和合并类型检查；数据库／harness 不并行，也不减免验收，必须保留固定 6 pair／12 case 矩阵。

32. **正式结果丢响应后的重载对账**
    - 决定：已保存正式项目在响应丢失后重载，必须挂载 GET 对账并显示已保存 raw，而不是只显示已保存数量。
    - 原因：规格要求显示已保存结果，并在重试前对账 pending。
    - 代价／权衡：需要 Task15 窄幅路由／hook 回归与修复；浏览器验收不得通过放宽断言掩盖未清理 pending。

33. **重载修复的精确匹配范围**
    - 决定：只对匹配现有账号／正式模式／套系／轮次／项目的 pending 挂载保存项目重载修复；无缓存时保持原有保存列表／报告入口。
    - 原因：`SessionView` 没有已提交 attempt ID，无条件挂 Host 会得到空的禁用视图。
    - 代价／权衡：不为没有 pending 的历史保存项新增 raw-detail URL；现有报告／历史仍可用，最后一项刚保存且仍有 pending 时，仍须对账并导航。

34. **竖屏结果证据放入主触屏流程**
    - 决定：竖屏保存结果／报告可达性和保存布局稳定性放在 `EA-TOUCH-SIM-002`，使用该用例实际经 UI 创建的记录；`EA-CAP-RESPONSIVE-003` 只覆盖入口／历史／trial。
    - 原因：capability fixture 重置后刻意没有已完成结果，伪造数据或放宽精确 DB 计数会破坏更强的隔离要求。
    - 代价／权衡：断言组迁移并需在验收矩阵中明确记录，覆盖本身不得丢失。

35. **Task17 冻结测试与部分验证先提交**
    - 决定：完整测试仍在运行时，可先提交已冻结 Task17 测试和如实的部分验证文档，以重叠独立静态评审。
    - 原因：提交未变化字节不会扰动运行进程，且已有 focused 86 证据。
    - 代价／权衡：完整结果后必须补充报告；不得由早期评审推断 Task17 已完成或可发布。

36. **浏览器验收与第二轮完整后端的顺序**
    - 决定：修复并评审首轮完整测试唯一 fixture 失败及静态／类型／配置问题后，先运行隔离的真实浏览器验收，再针对最终修正候选运行第二轮完整后端。
    - 原因：两者共用一个可重置数据库，浏览器集成也可能暴露额外代码变更；这些检查不要求特定的先后顺序。
    - 代价／权衡：浏览器先验证的是最终全量后端 green 之前的本地候选；仍须保留浏览器和最终全量后端两道必需发布门禁，且不接触生产。

37. **脱敏浏览器摘要的诊断字段**
    - 决定：修正真实用例标题解析，并在脱敏浏览器摘要中增加枚举型失败类别和严格 allowlist 的来源位置。
    - 原因：原始日志删除后仅保留聚合失败，无法诊断真实浏览器行为。
    - 代价／权衡：小幅扩展测试工具 schema 并增加恶意标记回归；不得持久化错误消息、原始结果、标识符或任意路径，所有既有验收门禁保持严格。

38. **候选 1ca41b4 的最终广域源码评审**
    - 决定：在浏览器工具诊断与验收继续时，对冻结应用候选 `1ca41b4` 启动一次广域最终源码评审；在已记录的席位上限例外下复用 `agent4`。
    - 原因：所有业务代码任务评审已绿，且广域 diff 很大，适合与独立只读工作并行；`agent4` 先前负责区域仍保留其独立任务评审证据。
    - 代价／权衡：后续修复必须做明确的范围化复审；在浏览器、设备、完整后端和部署门禁全部通过前，不得形成最终合并／发布结论。

39. **真实时钟的 Host 单调时间诊断**
    - 决定：允许使用临时、只读的 Host 单调开始／观测结束诊断来证明真实时钟运行。
    - 原因：DOM 提交延迟无法证明固定业务窗口，降低持续时间阈值又会削弱要求。
    - 代价／权衡：增加一个需维护的小型诊断面；它不得提供控制钩子、身份或评分 raw，必须每轮重置，且不得进入持久化 DTO 或留存制品。

40. **第二轮完整后端与前端复审并行**
    - 决定：在重新运行浏览器矩阵前，立即让第二轮完整后端与范围化前端复审并行；本决定取代此前“浏览器先于第二轮完整后端”的条件性顺序。
    - 原因：广域评审未发现后端改动，已提交的组合修复仅涉及前端，因此 Python 与浏览器 collection 输入已冻结，可利用空闲数据库窗口完成最终后端验证。
    - 代价／权衡：若真实浏览器工作改变 Python 或 CLI 契约，仍须重跑相应检查；不减免任何发布门禁，也不放宽数据库串行所有权。

41. **macOS 桌面验收使用真实窗口焦点**
    - 决定：仅 macOS 的电竞桌面 Playwright 项目使用可见浏览器，在测量开始前，通过该测试连接确认的唯一浏览器 PID 请求原生窗口激活；退出锁定验证向同一自有浏览器发送原生 Esc 按下／释放，不以页面脚本退出代替。
    - 原因：独立原生 API 探测证明 DOM focus 与 bringToFront 不足以获得 Pointer Lock，真实窗口激活后成功；随后 ERP 已进入试练，但 CDP Esc 未触发 macOS 原生退出键，独立原生按键对照成功解除锁定。不能因此放宽正式测试的鼠标锁定门槛。
    - 代价／权衡：本地验收会暂时占用前台窗口；不修改或模拟浏览器锁定／focus API，不激活其他用户窗口，不在测试中断后强行恢复焦点。Windows 和真手机仍需各自验收。
