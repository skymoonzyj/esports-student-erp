# 端游 FPS 固定靶区设计

日期：2026-11-10。状态：用户已确认，已按实施计划完成代码与隔离验收；NAS 发布结果见实施计划的执行记录。

## 用户确认的范围

- 仅调整天赋测试 2 的端游 FPS 网格射击与六目标射击。
- 固定靶区；所有当前目标在允许转动范围内始终完整可见，不仅要求刷新瞬间可见。
- 保留准星居中、鼠标转动视角的操作；限制转动范围，不能转到靶区之外寻找目标。
- 命中只替换被击中的目标；其他目标保持世界坐标，不随视角移动。
- 窗口和可选全屏都遵守相同规则。90°范围跟枪不改。
- 新规则独立版本、独立排名；保留旧成绩、旧报告及未完成记录。

## Approaches

1. **采用：固定世界角度网格＋固定相机转动边界。** 所有候选位置在整个合法转动范围内均可见，目标可精确瞄准；边界不随命中改变。
2. 不采用跟随视角移动未命中目标：会改变目标位置和肌肉记忆，用户不能依赖原位置继续瞄准。
3. 不采用二维鼠标光标点击：会改变现有 FPS 转动视角交互。

## 当前原因与工程默认值

现有 v4 按生成时的相机生成目标，未命中目标停留在原世界坐标，相机 yaw 却可转满一圈。因此“新目标生成时可见”不能保证转动后全部目标可见。

以下数值是满足已确认行为的工程默认值，不是用户逐项指定参数：

| 新版本参数 | 网格射击 | 六目标射击 |
| --- | --- | --- |
| 当前目标数 | 3 | 6 |
| 固定候选网格 | 5 × 3 | 5 × 5 |
| 网格间距 | 9°（v4 为 10°） | 6°（不变） |
| 相机 yaw | −18° 至 18° | −12° 至 12° |
| 相机 pitch / 登记 pitch_limit_deg | −9° 至 9° / 9 | −12° 至 12° / 12 |
| 水平视野 | 90° | 90° |
| 正式目标直径 | 6° | 1.5° |
| 练习难度 1–5 直径乘数 | 1.5、1.25、1、0.85、0.7 | 同左 |
| reference_hits | 300 | 150 |

正式测试和取得服务端练习票的练习均为 60 秒；不取票的本地试操作为 20 秒。上述时长、最小射击间隔 50ms、最多 1200 条射击记录，以及当前分数公式保持不变。不同难度不改变固定网格或相机边界。

## 固定布局与输入

候选按行、列依次生成：`yaw = (column - (columns - 1) / 2) * spacing`；`pitch = (row - (rows - 1) / 2) * spacing`。不是随相机旋转的锥面布局。原点为现有 INITIAL_CAMERA.position=(0,1.6,0)，目标距离 10，原点不重新居中。

从固定候选集合使用现有确定性随机数选点，排除刚击中位置以及与保留目标重叠的位置。相机只 clamp，不做 360°环绕；仍使用现有角度输入 `yaw + dx`、`pitch - dy`，不重复应用灵敏度。越界输入余量直接丢弃，反向移动立即响应。dx/dy 任一非有限时忽略本次 look，不污染相机。保留现有输入顺序、时间线、命中判定和 finish 幂等行为。

全部候选中心均在相机边界内，因此准星可以到达每一个中心。最大练习目标下，网格替换至少有 8 个候选、六目标至少有 19 个候选，不需要无限重试或偷偷缩小目标。

## 全目标可见保证

实际 canvas 保持现有 16:9，超宽外屏留边，不把外屏宽高当成游戏画布宽高。允许 `abs(width - height * 16/9) <= 1 CSS px` 的布局舍入误差，但仍按实际宽高验证目标完整轮廓至少留 1°视锥安全边距。沿用既有设备与最小尺寸检查；不因屏幕太小缩靶、改参或偷换版本。

对称相机边界 A=max|yaw|、B=max|pitch|，垂直半视野 v=atan(height/width)。当前小角度矩形内，候选球心到水平和垂直视锥边界的最坏角距可下界为：

```text
H = asin((cos²B*cos(2A) - sin²B - cosB*sin(2A)) / sqrt(2))
V = asin(sin(v-B)*cosB*cos(2A) - cos(v-B)*sinB)
余量 = min(H, V) - target_diameter_deg/2
```

实现使用弧度计算并回转角度，严格验证有限数值与正尺寸。16:9 最大练习目标下，网格余量约 2.983926°、六目标约 2.782464°，均超过 1°。旧网格间距 10°不能同时保证最难可见边界和所有中心可达，故新版本改为 9°。

测试还必须通过独立 Three.js 相机及完整球轮廓投影核对，不能只用生产可见性函数自证。连续范围保证来自解析边界，有限采样只作独立核对。

## 版本、成绩和兼容

- catalog_version、engine_version 新增并默认使用 `pc-fps-v5`。
- scoring_version、report_version 继续使用 `pc-fps-v4`，因为公式与报告规则未改。
- params.kind、raw.kind 仍是 `multi_target`，记录仍为 shots(at_ms, hit)；不新增不必要的传输类型或数据库迁移。
- v4 配置、引擎、fixtures 和旧成绩原样保留；v1–v3 老四项也保留。
- v5 三项仍为 gridshot、sixshot、spheretrack90。跟枪所属套题版本升级，但其参数、引擎行为、原始结果和计分不改。
- 沿用完整配置快照隔离排名池；v5 全套和各单项不与 v4 混排，包括新套题里的跟枪。前三、本人名次、差距功能继续适用。
- 已有正式轮次和练习票按保存的版本继续；创建重试使用原操作键并返回原快照，不偷换为 v5。旧轮次可以完成或按已有流程放弃，再开新轮次。
- 不清空恢复状态、重算历史、重命名 pending 存储键或更改当前仅端游 FPS 对外开放的开关。
- 本次不扩展服务器空间反作弊：现有 multi_target 原始数据不包含可供服务器重放的空间轨迹。

## 验收与发布

1. 两项 × 五档练习 / 正式配置：全部候选、相机四角/边界/内部，以及随机连续大幅输入下，完整球体不裁切、不重叠；保留目标不位移；所有中心可命中。
2. 命中后反复补位始终保持 3/6 个目标；无候选耗尽；固定随机种子可复现。
3. 旧 v4 引擎保留原行为；v4 待提交、幂等重试、报告和排行不受损；v5 排名独立。
4. 窗口/全屏、DPR 1/2、超宽外屏留边与尺寸变更；无 HUD 遮挡。非法 viewport 在创建正式 attempt 或练习 ticket 前明确拒绝。
5. 隔离账号在真实 Chrome 验证窗口和全屏，包含两项练习及正式保存/报告，90°跟枪回归。需要前台鼠标锁定时提前协调，不操作正式账号或制造正式成绩。
6. 完成适用回归、构建及代码复核后，通过标准 scripts/deploy-nas.sh 发布；备份/预检/部署失败为阻断。核实线上发布身份、健康和 catalog，不绕过脚本。

## 非目标

不改手游 FPS、MOBA、听声辨位、天赋测试 1、实体灯、UI 主题、分数阈值、全屏退出安全策略或用户权限。没有确认的真实浏览器验收不得写成已通过。
