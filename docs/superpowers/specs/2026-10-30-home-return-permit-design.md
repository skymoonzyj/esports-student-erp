# 回乡证人员证件支持

## Intent and authorization

用户明确要求新增回乡证选项，以便为两名学员及其监护人使用真实证件建档。沿用现有香港身份证扩展架构；不再次设计角色、账号或住宿流程。真实人员资料只在授权后台录入，不进入源码、测试或文档。

## Approaches

- 采用：独立 `hk_mo_permit` 证件类型，复用现有 typed identity、管理建档、监护人、更正、认领和激活路径。符合用户选择，且不混淆证件。
- 不采用：冒充香港身份证或护照，会改变校验、查重和档案事实。
- 不采用：任意证件自由文本，会绕开现有类型及隐私边界。

## Contract

- 类型 `hk_mo_permit`；显示“回乡证（港澳居民来往内地通行证）”，号码字段“回乡证号码”。适用于香港 H、澳门 M 字头的中国籍居民通行证；不扩展非中国籍通行证或其他证件。
- 校验 ASCII `[HhMm][0-9]{8}`，也接受其后紧接两位数字换证次数，规范化为大写字头＋8位终身号。仅去掉首尾空白，不接受内部空白、全角或其他字符；不虚构校验位。参考国家移民管理局 https://www.nia.gov.cn/n794014/n1050181/n1050479/c1197066/content.html 。支持可选换证次数是实施选择，避免同一人换证后重复建档。
- 服务端 `normalize_hk_mo_permit(number: str) -> str`，前端 `normalizeHkMoPermit(value: string) -> string | null` 使用相同规则；查重摘要域 `hk-mo-permit-identity`。不产生 passport_number_digest，document_issuing_country 仅允许 None，不推测地区或出生性别。
- 严格建档本人和监护人必须手工填写生日、性别，保留成年监护人校验；资料待补本人可暂缺事实，但激活前仍须补齐。监护人完整性要求不放宽，缺资料不伪造。
- 管理建档、资料待补、更正、学员及监护人、公开档案认领、后台认领审核、已有邮箱验证码激活完整贯通。仅更改证件类型能力，不增加授权、自动激活、短信服务或新的自助注册能力。
- 保留旧 CN/HKID/passport 号码摘要、密文、旧签名证据和关联关系，不自动迁移旧记录。
- 普通房态导出正确标注证件类型；现有只支持内地居民身份证的公安报送仍拒绝非 CN 证件。号码脱敏、敏感作废理由拒绝及审计不泄露保持一致。
- 数据库新增 0078_hk_mo_permit_documents，接在0077之后；只扩展现有约束。有该类型记录时拒绝有损降级。

## Acceptance

测试覆盖 H/M、9/11位同人查重、无效格式、本人/监护人、手工事实保持、旧证件兼容、真实数据库建档更正认领至OTP激活、未成年监护人门槛、迁移与降级、导出和隐私；桌面/手机及A/B主题表单无溢出。适用本地检查完成后通过标准脚本发布NAS并验证备份恢复。正式建档另行核对已登录管理员、重复人员、房间状态容量/性别及日期，不直接写数据库。
