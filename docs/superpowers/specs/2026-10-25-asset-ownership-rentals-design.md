# 资产归属、租期与续期

## 授权与目标

用户要求资产区分自有/租用；自有记录采购渠道或其他获得方式；租用记录租期、使用人、地点，剩余一周在工作台提醒，支持单个与批量按一周、一月、一季续期。用户回复“直接开发”，已选择跳过进一步问答/审批，沿用上一条建议：从原到期日顺延。以下未逐项指定的行为是实施方选择，不冒充用户逐项批准。

## 方案与边界

在现有资产台账、分配历史和权限上扩展，不另建租赁系统；独立租期不能复用使用人的预计归还时间或保修到期日。与另建完整合同/财务租赁系统相比，保留统一资产代码、照片、二维码和个人资产入口，不引入租金、押金、账单或付款联动。

- 新录入界面必选自有/租用。自有选择采购或其他；采购渠道线上/线下；其他必须填写获得方式。既有采购生成资产回填自有/采购及真实采购渠道；无法判断的历史资产保留空值显示“待确认”，不能猜测。旧 API 调用省略新字段时仍可建待确认资产以兼容现有流程，新界面必须选择。
- 租用必填开始与到期日期（含到期当天），年范围0001–9999，开始不得晚于到期。已有使用人、地点、照片、分配/归还历史继续使用。租赁日期与使用人的预计归还日互不改写。
- 一周=7天；一月/一季=1/3个日历月，月末夹到目标月最后一天。从原到期日顺延，包括已经逾期的资产；界面明确仍可能逾期。不可溢出9999年。
- 单个与批量使用同一个续期端点。每次最多100件明确选择的资产，按各自原日期延长相同周期；批量全成或全不成。锁定后校验版本；重复请求使用同一个操作键返回原结果，不重复续期或审计。每项保存原/新到期日、操作人和时间，可查看历史。
- 仅有效租用资产可续期；已退租、报废、自有、待确认不可续。普通编辑不能直接改变已开始记录的租赁归属或绕过续期修改到期日；日期录错可在尚无续期历史时经版本校验更正，必须审计。续期后仅能用续期动作延长。
- 独立“退租”动作填退租日期，必须先完成使用人归还，不自动替人归还、不改写租期；退租后保留资产和续期历史、停止提醒、禁止新分配及续期。已有报废资产不提醒。暂不提供退租撤销或再次启租。
- 工作台新增独立资产提醒；中国日期计算，到期差值0–7天（含第7天）及负数逾期均显示，未分配/维修中的有效租赁仍提醒。显示代码、名称、使用人、地点、到期日、剩余/逾期天数。按到期日期、代码、ID排序，分页；与离营提醒独立失败，不影响其他工作台内容。
- 读取提醒沿用全局assets.read，续期/退租沿用assets.manage；使用人分配沿用assets.assign。行政/超管原有权限保持，普通管理员不新增资产管理权限。个人资产/人员档案/二维码仅延伸原有可见资产的归属与租期，不新增财务、人员或其他资产读取权限。
- 资产列表与导出可筛选归属（含历史待确认）；导出追加归属、取得方式、渠道、租期、退租日期，不改变旧列含义。采购转资产显式记录自有采购，来源字段与售后字段分开。
- 普通租期日期仅年月日；审计和续期记录操作时间保留时分。提醒数据跨账号、权限变化、焦点恢复及中国午夜必须重新授权/刷新，不显示失权缓存。仅添加能力，不改变原来的房态、离营或财务功能。

## 验收

覆盖正常/闰年月末、逾期续期仍逾期、9999年、非法输入、缺失资料、普通管理员越权、重复提交、版本冲突、并发续期、混合批量回滚、退租与使用人归还区别、迁移历史保留、照片/导出/采购联动、提醒第7/8天与中国午夜、撤权缓存清除及窄屏操作。使用新建独立数据库和合成浏览器数据，不在NAS造测试人员/资产。通过适用检查后仅用标准deploy-nas.sh发布并验证备份、迁移、健康。
