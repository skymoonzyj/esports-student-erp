## 统计、保洁

保留上一版左侧基础条件决定统计范围、顶部快捷条件只过滤列表的逻辑。已用房间数使用 occupied_rooms，不另算人数；满房仍是容量大于零且达到容量。空房继续排除 problem/maintenance/disabled。总床位和房型统计排除问题/维修/停用/功能间，其他规则不变。

新频率 cleaning_frequency 为 unspecified/daily/weekly/on_demand。旧 true -> daily，旧 false -> unspecified。保留旧 daily_cleaning_enabled 兼容投影及查询：true 仅 daily，false 为非 daily；旧写 true -> daily，旧写 false -> unspecified；频率和旧布尔同时提交若冲突明确拒绝。新 UI 只使用频率，显示“未设置/每日保洁/每周保洁/按需保洁”。

顶部增加三个频率计数/快捷条件，旧未设置不计入任一频率。导出频率多选，同维度 OR，跨维度 AND，保留楼栋和其他筛选；导出条件可见可修改可清除。当前房态导出频率列显示中文值。保洁频率和 ready/pending 退房保洁状态始终独立，不因改频率清除待保洁，也不自动生成每日/每周清洁任务。既有管理员/行政/超管保洁配置权限不改；物业本期不新增保洁完成或照片管理权。

## 物业权限及审批

角色 key property，名称“物业”。复用现有角色指派 UI，默认仅查看房态、提交变更、住宿摘要/问题清单导出、房卡日期管理。审核权限仅行政和超管；普通管理员保留原有直接房态管理，不新增审批权或房卡日期管理权。多角色按权限并集与显式拒绝处理，角色身份门槛与楼栋/楼层范围同时检查。

物业提交不写实际房间、问题、容量或核对状态。申请记录保存房间、原版本、原值、建议值、原因、提交人、提交时间及审批结果。允许变更服务状态、房型/与其一致的容量、备注/问题说明；不允许修改房号、楼栋、楼层、删除房间或办理住宿。功能房转换必须遵守现有真实住宿/预约冲突及容量规则。

一房至多一条待审申请；可撤回本人申请。审核人不得审批自己的申请。驳回必须有原因。审批通过在同一事务锁申请及房间、重验当前双方权限、原版本、目标约束，执行一次，写审计；重复请求不重复生效。房间版本已经变化时拒绝通过，要求撤回重提，不覆盖新改动；权限撤销或提交人停用不能靠旧申请继续生效。通过服务状态变更继续遵循原自动核对规则，但不自动解除退房保洁。

物业能读自己提交的申请；审核者能读获授权范围内申请。房态概览提供审批面板，房间详情提供提交入口。不把未审核意见混入已生效的统计或导出。

## 导出与隐私

新增独立非实名报送导出，不把 housing.reports.export_sensitive 直接授予物业。

- 住宿列表：楼栋、楼层、房号、姓名、昵称、性别、实际入住日期、计划离开日期（常住明确标注）、房卡开卡日、到期日。仅当前有效在住/待退宿，排除已退房/作废/预约；默认不输出完整身份证、手机号、邮箱、监护人资料。原有敏感导出及其权限保持。
- 问题房清单：获授权的全部 problem/maintenance/disabled 房间，含楼栋、楼层、房号、房型、服务状态、房间备注和未解决问题说明；不包含住客敏感资料。不受当前页限制，可按楼栋选择。
- 两类支持 XLSX/CSV，要求用途，审计、公式注入防护、导出前后权限复验、无共享缓存，不能从摘要入口扩大到完整历史或实名报送。

## 房卡与提醒

使用独立 housing_room_cards 表，以 stay_id 唯一关联一次住宿，存开卡日/到期日及版本；旧住宿不虚构日期。两日期均为空表示尚未录入；保存须同时填写且到期日不早于开卡日；年限 0001–9999，界面只显示年月日。日期独立于计划退宿日，到期日当天有效，不对接或控制门锁硬件。

房间详情列出现有在住人员的房卡信息，超管/行政/物业可按现有楼栋范围单独编辑，操作审计并检查版本和当前有效住宿。普通管理员、教练及本人不因查看获得编辑权。退房/调出后禁止继续修改该住宿的房卡；调房形成新住宿，新房卡日期为空，旧记录及审计保留。不影响旧入住/退房事务。

工作台新增只读房卡提醒，按中国时间日期 D 选 expires_on <= D+7 的有效 checked_in/checkout_pending 住宿，包含已过期；未激活人员也能出现在管理人员名单。超管/行政仅见已有房态范围内人员，其他账号仅见自己；物业若非行政/超管仅获本人提醒，不额外全局提醒。即将到期、今日到期、已过期中文区分，显示姓名/昵称、房号、到期日、剩余天数。后端分页，计数先授权后计算；不含证件/电话/室友。更新日期、退房、跨中国时间零点、账号/权限切换后刷新，不展示旧身份结果。
