# 阶段 1B 教练与家庭门户设计

**日期：** 2026-07-29
**状态：** 已实现并通过本地门禁，待后续 Docker/NAS 统一复核
**所属阶段：** 阶段 1B 第三个模块；承接已完成的教学配置与招生报名

## 1. 目标

本模块把现有统一 ERP 工作台扩展为教练、监护人和学员可实际使用的只读门户。完成后系统必须能够：

1. 让教练登录后一键打开本人负责的最近下一期学员名单，并切换查看更晚营期。
2. 让监护人切换查看有效关系内的多名未成年或成年学员，以及学员的当前、即将开始和历史教学信息。
3. 让拥有启用账号的学员查看本人教学信息；未成年学员继续受现有监护人就绪规则约束。
4. 让当前付款账号查看自己的付款与退款，不因家庭关系获得其他付款人的付款信息。
5. 让同时具有教练、监护人或学员身份的账号在同一工作台中使用全部获权功能，无需退出登录或重新选择身份。
6. 在 360、768、1024 和 1440 四种宽度下完成相同核心旅程。

## 2. 范围

### 2.1 本模块包含

- 统一任务卡片首页和动态门户导航。
- 教练下一期营期、班级和正式报名学员名单。
- 家庭学员切换器和本人/家庭教学历史。
- 当前付款账号自己的付款与退款页面。
- 门户专用最小响应模型、对象级权限、私有缓存策略和错误处理。
- RBAC 权限、默认角色授权、必要查询索引和顺序数据库迁移。
- 后端、前端、迁移、E2E 和四视口响应式验收。

### 2.2 明确不包含

- 每日或每周教练评语及评价数据表。
- 截图上传、OCR、自动评价、游戏 ID 和录像/GPU 分析。
- 楼栋、房间、床位、房态、入住人员及实名导出。
- 用户自助注册、公开项目选择、支付跳转和真实支付平台适配器。
- Docker/NAS 打包、容器启动和迁移；这些在后续模块完成后统一处理。

家庭教学页本阶段显示“学习评价 · 下一阶段开放”的不可操作卡片，不创建空评价页面，不请求不存在的评价接口，也不提前创建评价数据。

## 3. 既有基础与当前缺口

当前代码已完成阶段 1B 的教学配置和招生报名：项目、职业队伍、营期、普通班/菁英班、教练分配、付款、退款、待分配、正式报名、转班和退营退费均已存在。

本模块直接复用：

- `people`、`student_profiles`、`guardian_relationships` 和监护就绪策略。
- `cohorts`、`teaching_classes`、`game_projects`、`professional_teams` 和 `coach_assignments`。
- `enrollments`、`payments`、`payment_refunds` 及其既有状态和约束。
- 会话、CSRF、强制改密、账号停用、审计、统一 Problem Details 和私有路由能力。
- `global`、`self`、`family`、`person`、`assigned_class` 对象范围及显式拒绝优先规则。

当前尚不存在门户上下文、教练下一期、家庭反向枚举、家庭教学或本人付款接口；前端也没有对应路由、页面或多角色首页。现有后台响应包含门户不需要的内部字段，不得直接作为门户契约。

## 4. 核心设计决策

### 4.1 统一工作台

同一账号可以同时拥有教练、监护人和学员身份。登录后不要求选择身份，也不创建分离会话。首页使用已确认的“任务卡片”布局：

- 教练工作：显示最近下一期摘要和“查看名单”入口。
- 家庭信息或我的学习：显示可查看学员数量和教学入口。
- 本人付款：显示当前账号的付款入口。

单一身份账号只看到对应卡片。多身份账号同时看到多张卡片，进入模块后仍通过独立导航保持边界清晰。

没有任何门户能力的纯管理员、客服或其他工作人员继续使用现有后台工作台，不会落入空白门户。工作人员同时拥有教练、监护人或学员身份时，后台快捷入口和门户任务卡片在同一首页共存。

### 4.2 专用门户接口

采用专用门户读接口，不扩宽现有后台列表，也不创建单一巨型工作台响应。理由是：

- 教练、家庭和付款范围的授权来源不同。
- 门户只应返回最小字段，不能依靠前端隐藏后台字段。
- 独立查询便于撤权、缓存失效、分页、测试以及后续接入评价模块。

### 4.3 只读投影，不复制业务数据

门户是现有业务模型的只读投影。数据库不新增门户业务表，不复制营期、报名、付款或人员数据。仅通过新迁移增加权限种子和经查询计划验证确有必要的索引。

## 5. 模块架构

### 5.1 后端边界

新增 `app.portal` 只读投影包：

- `router`：门户 HTTP 路由、依赖和统一私有响应。
- `schemas`：门户专用最小响应模型。
- `context_service`：计算当前账号可见的门户区域和学习模式。
- `coach_service`：下一期营期、班级和名单查询。
- `learning_service`：家庭/本人学员枚举及教学历史查询。
- `payment_service`：当前付款账号自己的付款与退款查询。

服务直接使用 SQLAlchemy `Session`，遵循现有架构，不为本模块引入 repository 抽象。`app.portal` 可以读取现有领域模型并调用 `RbacService`、`GuardianReadinessPolicy` 和审计服务；现有身份、教学和招生模块不反向依赖门户。

### 5.2 前端边界

前端新增独立门户区域，按职责拆分：

- 门户 API 类型与调用。
- 统一任务卡片首页。
- 教练下一期页面。
- 学习信息页面及学员切换器。
- 本人付款页面。
- 门户响应式样式和角色无关的状态/时间/金额格式化复用。

后台营期、报名和付款页面继续服务管理员与客服，不作为家庭或教练门户页面复用。现有全局设计令牌、会话提供器、QueryClient 和响应式外壳继续使用。

## 6. 权限设计

### 6.1 权限和默认授权

新增权限：

- `coach_roster.read`：查看本人负责班级的教练名单投影，固定 UUID 为 `20000000-0000-4000-8000-000000000025`。

默认角色授权调整为：

| 角色 | 权限 | 范围 |
| --- | --- | --- |
| 管理员 | `coach_roster.read` | `global` |
| 教练 | `coach_roster.read`、`enrollments.read` | `assigned_class` |
| 监护人 | `teaching.read`、`enrollments.read` | `family` |
| 监护人 | `payments.read` | `self` |
| 学员 | `teaching.read`、`enrollments.read` | `self` |
| 学员 | `payments.read` | `self` |

既有教练 `teaching.read/assigned_class`、监护人 `people.read/family` 和学员 `people.read/self` 保持不变。客服、生活老师和其他员工不因本模块获得新的默认门户权限。

`payments.read` 仍是敏感权限。`self` 授权只在不接受任意账号或人员编号的 `/me/payments` 中解释；不能因此进入后台付款列表。

所有权限继续执行：账号级显式拒绝优先于账号级允许和角色默认允许。带具体班级或人员范围的覆盖规则必须在门户查询的每个对象上重新判断。

### 6.2 门户上下文不是授权凭证

`GET /portal/context` 返回当前账号可以显示的门户区域，但只用于导航和文案，不替代各业务接口的服务端授权。

上下文通过账号状态、角色/人员类型和通用范围令牌计算：

- `coach`：教练身份且 `teaching.read`、`coach_roster.read` 和 `enrollments.read` 均在通用 `assigned_class` 令牌上有效。即使当前没有下一期，仍可进入教练空状态。
- `learning`：监护人的 `people.read`、`teaching.read` 和 `enrollments.read` 均在通用 `family` 令牌上有效，或当前人员是学员且三项权限均在本人 `self` 令牌上有效。
- `payments`：当前账号具有 `payments.read/self`。
- `learning_mode`：`self | family | self_and_family`，仅决定标题和切换器形态。

接口不把完整角色列表或具体授权规则交给前端。卡片显示不保证某个具体对象可读，数据接口仍逐对象授权。

### 6.3 对象范围规则

#### 教练

教练班级范围必须同时满足：

- `coach_assignments` 在同一个请求时间快照上已生效、未到期且未结束。
- 教练人员未删除，账号处于启用状态并仍具有教练角色。
- `coach_roster.read` 和 `enrollments.read` 对该班级均允许。

分配结束、账号停用、教练角色移除或显式拒绝生效后，下一个服务端请求立即移除对应班级。

#### 监护人

家庭范围只包含业务日期上已经开始、尚未到期且未结束的监护关系。学员成年不自动结束关系；只要关系仍有效，监护人继续查看该成年学员。关系结束或到期后，学员立即从家庭集合消失。

业务日期和成年状态统一按 `Asia/Shanghai` 计算；`valid_until` 当日仍然有效。

#### 学员本人

当前账号人员必须拥有学员档案，目标人员必须是本人。未成年学员账号在最后一名有效监护人失效时继续由现有策略自动停用并撤销会话；门户不复制该判断。

#### 当前付款人

本人付款固定过滤 `payments.payer_account_id == 当前 account_id`。家庭关系不扩大付款范围，同一学员的另一名监护人付款不可见。`payer_account_id` 为空的手工付款继续只在后台可见。

## 7. API 契约

所有接口位于 `/api/v1`，使用当前 Cookie 会话、CSRF 约定、请求 ID、统一 Problem Details 及 `Cache-Control: private, no-store`。

### 7.1 `GET /portal/context`

返回：

- `coach_available`
- `learning_available`
- `payments_available`
- `learning_mode`：`self | family | self_and_family | null`

不返回角色权限明细、班级 ID 清单、监护关系内部状态或付款金额。

### 7.2 `GET /coach/next-cohorts`

查询参数：

- `anchor_cohort_id`：可选；选择某个已授权后续营期所在的开营时间组。
- `page`、`page_size`：名单分页，`page_size` 最大 100。

服务端在请求开始固定一个带时区的 `now`，同时用于教练分配、营期筛选和 RBAC 判断。候选必须满足：

- 营期状态为 `open | upcoming`。
- `starts_at > now`。
- 班级在教练当前有效分配及权限范围内。
- 名单只包含正式报名状态为 `active` 的学员。

未提供 `anchor_cohort_id` 时选择最小 `starts_at`。同一个 `starts_at` 下教练获权的全部营期和班级一起返回；同一营期内的多个获权班级也全部返回。可选时间组只包含教练真实获权的后续营期。

响应包含：

- 当前时间快照和选中的 `starts_at`；无下一期时为空。
- 可切换的后续开营时间/营期摘要。
- 选中时间组内的营期、项目、班级、班型、职业队伍及主教练/助教身份摘要。
- 分页名单：报名 ID、学员 ID、姓名、学员编号、成年状态、营期、项目、班级、班型、教练分配身份和报名状态。

响应不得包含身份证、手机号、邮箱、监护人、约定学费、付款状态或任何金额。名单稳定排序为开营时间、营期 ID、项目排序、班级名称/ID、学员姓名/ID。

教练没有下一期时返回 `200` 和空集合，不回退显示 `draft`、`active`、`completed`、`archived` 或历史班级。传入不在获权选项中的 `anchor_cohort_id` 时使用掩码 `404`。

### 7.3 `GET /family/students`

候选集合为：

- 当前监护人在业务日期上的全部有效关系学员。
- 当前账号本人对应的学员档案。

每个候选都必须是未删除学员，并分别通过 `people.read`、`teaching.read` 和 `enrollments.read` 的 `family` 或 `self` 决策；任一必要能力被显式拒绝时不进入切换器。

响应只返回：学员 ID、姓名、学员编号、成年状态、访问来源 `self | family` 及当前/即将开始报名的最小摘要。默认排序为当前在营、最近即将开营、其余姓名/ID。没有候选时返回 `200` 空集合。

### 7.4 `GET /family/students/{student_id}/teaching`

接口同时校验目标学员的 `people.read`、`teaching.read` 和 `enrollments.read` 对象范围。不存在和越权统一返回掩码 `404`。

响应包含：

- 学员最小摘要：ID、姓名、学员编号、成年状态和访问来源。
- 当前、即将开始及历史报名分页列表。
- 每条报名的营期名称和时间、项目、班级、班型、可选职业队伍、报名状态及确认/取消/完成时间。

响应不包含付款、待分配单、学费、身份证、手机号、邮箱、监护诊断、教练联系方式或后台操作上下文。

教学列表先显示当前在营和即将开始的有效报名，再按开营时间倒序显示完成或取消历史；稳定排序最终使用报名 ID。

### 7.5 `GET /me/payments`

查询参数只有 `page`、`page_size`，不接受账号、人员或学员 ID。服务端同时要求 `payments.read` 在当前账号 `self` 令牌上有效，并固定按 `payer_account_id` 过滤。

响应包含：付款引用、来源类别、金额、币种、付款时间、退款总额、净额、推导状态以及退款金额、时间和类别。内部手工备注、退款内部原因、外部订单号、导入原文、服务账号和冲突信息不返回。

付款已经关联学员时，只有当前账号仍对该学员拥有 `people.read/family|self` 时才返回学员姓名；关系结束后付款记录仍属于付款人，但关联学员显示为“历史付款”，避免通过财务历史继续读取已撤回的学员身份。

每次成功返回金额都追加金额查看审计，记录操作者、结果条数、请求 ID 和成功结果，不把姓名、手机号、身份证、金额原文或私有负载写入日志元数据。

## 8. 页面与交互

### 8.1 统一任务卡片首页

首页先读取门户上下文，再并行读取获权卡片的轻量数据。采用用户确认的布局：教练、学习和付款卡片并列或纵向排列，各自提供唯一主操作。

- 教练卡显示最近下一期开营时间、可见班级数和学员数；没有下一期时显示“暂未安排下一期”。
- 学习卡按 `learning_mode` 显示“我的学习”“家庭信息”或“学习信息”，并显示可切换学员数量。
- 付款卡只说明可查看本人付款，不展示其他家庭成员付款。

纯后台账号保留现有工作台内容；门户卡片是按能力增加的区域，不删除管理员或客服已经可用的后台入口。

### 8.2 教练下一期页面

默认自动打开最近开营时间组，实现一键进入。页面顶部提供后续时间组切换，主体按营期和班级分组。

桌面端使用紧凑名单；手机端每名学员转为卡片。姓名、学员编号、成年状态、班级和报名状态是核心字段，任何视口都不能通过横向滚动才能读取或操作。

### 8.3 学习信息页面

监护人具有多个学员时显示切换器；只有本人时不显示多余切换控件。默认选择排序后的第一个可见学员，切换后 URL 和 Query key 都包含 `student_id`。

页面先显示当前或即将开始的报名摘要，再显示历史报名。学习评价卡片固定显示“下一阶段开放”，不可点击且不会产生网络请求。

若当前选中学员因关系结束而失权，前端清除该学员查询缓存，重新读取候选；仍有候选时选择第一个，无候选时返回工作台空状态。

### 8.4 本人付款页面

列表显示付款、累计退款、净额和状态。付款金额使用人民币统一格式，退款作为付款下的明细展示。页面不提供退款、匹配、编辑、导出或后台详情入口。

### 8.5 导航与多身份

导航条目由门户上下文和既有后台权限共同决定：

- 多身份账号同时显示教练和学习入口。
- 学员本人和家庭教学共用学习页面，不产生两套重复组件。
- 拥有后台权限的员工继续看到后台模块；门户入口不会取代管理员和客服导航。
- 手机底栏优先显示首页、教练、学习和更多；付款可在卡片或“更多”中进入，具体位置由可见条目数量决定。

前端路由固定为：

- `/`：统一任务卡片首页。
- `/coach/next-cohorts`：教练下一期页面。
- `/learning`：读取候选并进入默认学员。
- `/learning/:studentId`：本人或家庭教学页。
- `/me/payments`：当前付款账号的付款与退款。

同一学习组件处理 `self`、`family` 和 `self_and_family`，不创建按角色复制的页面。

## 9. 响应式与可访问性

固定验收：

| 宽度 | 布局 |
| --- | --- |
| 1440 | 完整侧栏、任务卡片网格、紧凑名单和完整筛选 |
| 1024 | 侧栏保留，名单只保留核心列，内容区不得裁切 |
| 768 | 顶部导航、两列卡片、次要字段进入详情卡 |
| 360 | 底部导航、单列任务卡、下拉学员切换、名单转卡片 |

额外要求：

- 不依赖 `overflow-x: hidden` 掩盖真实裁切；测试必须检查关键按钮和单元格边界。
- 触控目标至少 44px，底部导航不遮挡最后一项内容。
- 长姓名、空状态、错误提示和状态标记不得破坏布局。
- 键盘能够完成导航、时间组切换、学员切换和付款明细展开；焦点可见并在错误或路由变化后落到合理位置。
- 767→768、1023→1024 断点需额外验证，避免现有不同模块断点规则造成混合布局。

## 10. 缓存、撤权与错误处理

### 10.1 客户端缓存

门户查询使用独立 Query key，至少包含接口、当前账号范围、`student_id`、选中营期和分页参数。页面进入、切换学员和窗口重新聚焦时重新取数；退出登录、账号刷新或权限错误时清除相关缓存。

服务端授权始终是最终边界。已经渲染到浏览器的内容无法被远程收回，但关系或权限变化后任何新请求立即拒绝，前端在下一次进入/聚焦/切换时移除旧内容，不把曾经成功的缓存当作持续授权。

### 10.2 稳定行为

| 场景 | 接口 | 页面 |
| --- | --- | --- |
| 教练没有下一期 | `200` 空集合 | 明确空状态 |
| 教练分配结束 | 下次查询移除班级 | 清除名单并返回工作台提示 |
| 监护关系结束 | 家庭列表移除，旧地址掩码 `404` | 清除学员缓存并选择剩余候选 |
| 显式拒绝生效 | `403` 或对象掩码 `404` | 隐藏入口，不展示内部规则 |
| 付款权限撤回 | `403`，不返回金额 | 移除卡片并清空付款缓存 |
| 网络或服务故障 | 统一 Problem Details | 显示可重试错误，不伪装为空数据 |
| 会话失效或账号停用 | `401 invalid_session` | 清空全部数据并返回登录页 |

所有列表使用稳定分页和排序。输入无效返回 `422 validation_error`；具体对象越权不得通过错误差异暴露其是否存在。

## 14. 已确认决策摘要

- 同一账号使用统一任务卡片首页，不在登录时选择身份。
- 采用门户专用最小接口，不复用后台宽响应，不创建巨型工作台接口。
- 教练默认一键打开最近下一期；同一开营时间的获权班级一起显示，可切换更晚营期。
- 监护人查看所有有效绑定学员，成年关系继续生效；学员本人只看自己。
- 当前付款账号只看自己的付款与退款，家庭关系不扩大付款范围。
- 学习评价卡片显示“下一阶段开放”，本阶段不创建评价页面或数据。
- 关系、分配或权限变化后，服务端下次请求立即重新授权，前端清理对应缓存。
- 固定验收 360、768、1024、1440；Docker/NAS 迁移最后统一处理。
