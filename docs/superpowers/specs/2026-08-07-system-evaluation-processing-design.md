# 阶段 2 系统评价截图处理设计

- **日期：** 2026-08-07
- **状态：** 已逐段确认，待实施计划
- **所属阶段：** 阶段 2 第三实施单元
- **上游规格：** `2026-07-30-teaching-evaluation-center-design.md`
- **ERP 基线：** `7d7f390`
- **评分工具基线：** `20e1a38`

## 1. 背景与目标

评价中心页面整合与正式数据/媒体基础已经完成本地实现。ERP 已具备评分工具登录桥接、独立/内嵌只读页面、
工作人员服务历史、游戏 ID、辅助手机号、版本化分析配置、私有媒体存储和对象范围权限，但尚未开放浏览器
截图上传，也没有评价任务、Worker、OCR/评分结果、人工审核、发布或修订流程。

本实施单元交付“系统评价”业务分支，使获权学员、监护人、教练、工作人员和管理员可以在营期窗口内上传
游戏截图，并由独立评分 Worker 完成 OCR/规则评分。ERP 负责匹配、任务状态、审核、发布和全部历史版本，
学员及有效监护人只能查看已发布结果。

完成后必须满足：

1. 独立评分页面和 ERP 内嵌页面共用 ERP 账号、权限、任务与历史。
2. ERP PostgreSQL 是上传归属、任务、结果、审核、发布和版本历史的唯一业务主记录。
3. 新截图只进入 ERP 私有媒体目录，不进入评分工具 SQLite 或公开 `uploads/`。
4. 英雄联盟、无畏契约、和平精英可运行现有 OCR/评分能力，但首版结果全部人工审核。
5. 其他项目仍可上传并走人工录入，不因缺少自动适配器而被排除。
6. Worker 可重启、续租、重试，不允许旧尝试覆盖新尝试。
7. 上传、匹配、处理、审核、发布、驳回和修订均可追溯且不泄露敏感资料。

## 2. 范围

### 2.1 本单元包含

- ERP 与 `game-score-tool` 的版本化 v2 HTTP 契约。
- 获权目标选择、截图上传、媒体归属确认和任务创建。
- 项目游戏 ID、主手机号、辅助手机号的受限自动匹配。
- 系统评价任务、媒体槽位、Worker 尝试、租约、结果版本和审核历史。
- 英雄联盟、无畏契约、和平精英的现有 OCR/评分适配器接入。
- 未认证或不支持项目的人工录入流程。
- 待匹配、公共人工队列、审核、驳回、整改、发布和修订。
- 学员/家庭已发布历史、工作人员范围历史和管理员运营页面。
- 桌面、平板、手机共用的响应式独立/内嵌页面。
- 两仓库契约测试、真实 PostgreSQL 集成测试和本地四视口 E2E。

### 2.2 明确延期

- 录像上传、视频任务、GPU 分析和视频评价；页面只保留禁用入口。
- 训练 OCR/识图模型或承诺全部项目自动分析。
- 日报、周报、营期结营问卷和工作人员打印；它们属于后续独立单元。
- 旧 SQLite、旧截图、旧录像或运行目录的数据迁移与删除。
- Docker、Compose、NAS、媒体卷、生产 Tesseract/GPU 镜像和生产备份恢复。
- 生产自动发布；首版本单元的三个自动适配项目仍统一进入人工审核。

本单元不得修改 Docker/NAS 状态，也不得把本地 OCR 或 E2E 通过描述为生产适配器已经验收。

## 3. 已确认的核心决策

1. 采用“ERP 编排、评分工具执行”：ERP 保存正式状态，评分工具只提供页面和计算能力。
2. 截图文件进入 ERP 私有媒体目录，评分工具不保存新业务截图。
3. 使用独立本地 Worker 异步处理；租约 5 分钟，最多自动尝试 3 次。
4. 英雄联盟、无畏契约、和平精英运行现有适配器但强制人工审核；其他项目人工录入。
5. 管理员可配置 `auto_publish | review_required`，但只有已认证适配器才可能自动发布。
6. 低置信、缺失关键字段或存在阻断警告时始终强制审核。
7. 上传截图不算评价创作；人工录入、修改字段、调分或创建修订的人不能审核自己的版本。
8. 系统评价保留 0–100 分、等级、分项说明和建议；不与结营问卷 1–10 分互相换算。
9. 已发布版本不可覆盖；修订创建新版本，旧版本长期保留。
10. 旧评分工具正式数据和媒体不读取、不迁移、不修改、不删除。

## 4. 架构与仓库边界

### 4.1 ERP

ERP 负责：

- 当前账号、上传能力、可见学员、报名和项目。
- 上传会话、媒体校验、私有存储和媒体归属。
- 自动匹配、待匹配确认和业务去重。
- 任务状态、配置快照、Worker 租约和尝试记录。
- 结构化结果、人工录入、审核、发布和修订版本。
- 学员/家庭、工作人员和管理员查询投影。
- 权限、审计、错误和禁止缓存边界。

新增代码继续位于 `app.evaluations`，按任务、处理、审核和集成契约拆分，不能继续扩大现有大型管理路由。

### 4.2 `game-score-tool`

评分工具负责：

- 保留现有独立/内嵌页面及视觉结构。
- 通过 ERP v2 契约获取获权上下文、上传和任务历史。
- 运行独立 Worker，领取任务并执行 OCR/评分适配器。
- 把结构化字段、置信度、警告、评分和版本信息提交 ERP。
- 在网络失败时使用同一幂等键重传，不维护正式业务状态。

评分工具不得导入 ERP ORM，不得把服务凭据发给浏览器，也不得使用 `database.py` 或本地 SQLite 保存新业务
记录。现有 `data/`、`uploads/` 和 `runtime/` 仅作为旧数据/运行目录保留，不能成为新流程依赖。

### 4.3 运行组件

本地开发同时运行：

- ERP PostgreSQL。
- ERP API。
- ERP React Web。
- 评分 Web。
- 评分 Worker。

评分 Web 与 Worker 使用不同的 ERP 服务身份。Web 身份只代理获权用户操作；Worker 身份只领取任务、读取
当前租约媒体、续租和提交本次尝试结果。

## 5. 端到端数据流

1. 用户从独立或内嵌评分页面进入，评分工具通过既有登录桥接获得短期委派会话。
2. 评分 Web 向 ERP 查询当前账号可上传的学员、报名、项目、窗口和所需截图槽位。
3. 用户选择目标并上传 1–3 张截图；评分 Web 流式转发到 ERP，不落入评分工具长期目录。
4. ERP 在隔离临时区校验授权、窗口、文件格式、大小、像素、解码、哈希和任务去重。
5. ERP 原子提交媒体、归属、任务和创建审计，并固化当前分析配置快照。
6. 目标明确时，自动项目进入 `queued`，人工项目进入 `manual_input`；目标不唯一时进入 `pending_match`。
7. Worker 原子领取 `queued` 任务，取得租约与短时媒体读取票据，运行适配器并提交结果。
8. ERP 验证服务身份、任务版本、尝试编号、租约和幂等键后保存结构化结果。
9. 首版自动结果进入 `needs_review`；人工草稿提交后同样进入 `needs_review`。
10. 独立审核人通过后发布；驳回后原录入/修改人创建整改版本再提交。
11. 学员、有效监护人和获权工作人员只读取当前已发布版本及允许的历史。

## 6. 数据模型

### 6.1 `system_evaluation_tasks`

任务至少保存：

- 稳定 UUID、面向页面的任务编号和乐观锁版本。
- 上传人账号/人员、目标学员、正式报名、项目；待匹配时目标允许为空。
- 创建时的上传窗口、分析配置 ID/版本及完整不可变配置快照。
- 当前状态、当前尝试、自动尝试次数和人工队列原因。
- 当前结果版本、当前已发布版本和直接修订前驱任务/版本。
- 创建、匹配、处理、审核、发布、归档时间和对应操作人。
- 安全失败代码；不得保存原图、完整 OCR 原文或自由文本异常堆栈。

任务不允许物理删除。目标确认后，学员、报名和项目只能通过受审计的专用动作写入，不能普通更新。

### 6.2 `system_evaluation_task_media`

每行关联一个现有 `evaluation_media_assets`：

- `task_id`、`media_id`、顺序和项目定义的用途槽位。
- 同一任务最多 3 张，同一槽位不可重复。
- 媒体归属确认后，任务、学员、报名和项目必须一致。
- 业务去重使用学员、报名、项目和媒体哈希，不向无权上传者透露其他任务存在性。

和平精英首版提供个人数据、结算战绩和队伍明细三个槽位；具体必填槽位来自任务配置快照。英雄联盟和
无畏契约同样由配置返回槽位，不由前端硬编码。

### 6.3 `system_evaluation_attempts`

每次自动处理保存：

- 任务 ID、单调递增 `attempt`。
- 适配器标识/版本、评分规则版本和结果模式版本。
- Worker 服务身份、租约令牌摘要、领取/续租/到期/完成时间。
- 尝试状态、错误分类、是否可重试和安全错误摘要。
- 结果提交幂等键摘要和追踪 ID。

数据库唯一约束保证同一任务/尝试只有一行。明文租约令牌不入库；只保存不可逆摘要。

### 6.4 `system_evaluation_result_versions`

每个版本保存：

- 任务、版本号、来源 `automatic | manual | correction | revision`。
- 结构化识别字段及其置信度。
- 规则警告代码和阻断级别。
- 0–100 总分、等级、分项说明和系统建议。
- 适配器/规则/模式版本以及任务配置快照引用。
- 创建者、审核者、审核结果、驳回原因和发布时间。
- 前一版本 ID，形成不可变版本链。

完整 OCR 原文默认不保存。确需诊断的脱敏片段必须使用独立字段、有限长度、单独权限和后续保留策略。

### 6.5 审核与事件历史

审核、驳回、重新开放、归档、发布和修订动作保存追加式事件或专用历史行。自由文本原因保存在受权业务
字段中，审计元数据只保存安全 ID、状态、版本、计数和公开错误码。

### 6.6 幂等

上传提交、任务创建、结果提交、人工版本提交和审核动作各使用独立作用域的幂等键。相同键和相同载荷返回
原结果；相同键但载荷不同返回冲突并审计。幂等载荷摘要不得建立包含实名明文或完整 OCR 的可比对摘要。

## 7. 上传资格、窗口与媒体校验

### 7.1 上传资格

上传窗口按 `Asia/Shanghai` 为开营前第 7 天 `00:00:00` 至结营后第 7 天 `23:59:59.999...`，截止瞬间包含。

允许主体：

- 窗口内正式报名学员，且账号具有上传权限。
- 获权监护人代有效家庭范围内学员上传。
- 与报名对应项目/班级存在实际服务重叠且仍在窗口内的获权工作人员。
- 管理员代获权范围内学员上传；必须填写业务原因。

`evaluation_center.access` 不自动授予上传。账号停用、显式拒绝、授权到期、家庭关系结束或服务范围不匹配时
下一次请求立即拒绝。非正式报名或非青训营人员不能创建任务。

### 7.2 文件规则

- 仅 JPEG、PNG、WebP。
- 单张最大 20 MiB、最大 5000 万像素。
- 每任务最多 3 张。
- 扩展名、声明 MIME、嗅探 MIME 和实际解码必须一致。
- 预览由服务端重新解码生成并去除元数据；原图不直接内联。
- 解码炸弹、截断、伪造类型、尺寸超限和不安全元数据必须失败关闭。

上传先写入 ERP 媒体存储的隔离临时区。只有文件和业务事务全部成功才转为长期对象；失败临时文件进入有界
清理队列，不能成为长期孤立媒体。

## 8. 匹配与目标确认

上传页面优先使用用户明确选择且已获权的学员、报名和项目。没有明确上下文时，仅在上传人本来有权访问的
窗口内目标中执行身份提取，顺序固定为：

1. 当前有效的同项目游戏 ID。
2. ERP 主手机号。
3. 管理员维护的辅助手机号。

唯一命中才可自动确认。零命中或多命中进入 `pending_match`，停止正式 OCR/评分。浏览器只得到“需要确认”
状态，不返回候选姓名、手机号、游戏 ID、命中数量或无权目标存在性。

学员可管理本人游戏 ID；监护人只有获得家庭范围管理权限后才可管理；管理员可确认目标。确认后按任务创建
时配置进入 `queued` 或 `manual_input`，并重新校验上传窗口、报名、权限、游戏 ID 生效时间和媒体业务去重。

## 9. 状态机

主状态：

```text
uploaded -> identifying
identifying -> pending_match | queued | manual_input
pending_match -> queued | manual_input
queued -> processing
processing -> needs_review | failed
failed -> queued | manual_input | archived
manual_input -> needs_review
needs_review -> published | rejected
rejected -> correction_pending | archived
correction_pending -> needs_review | queued
archived -> correction_pending | queued
published -> revision_draft
revision_draft -> queued | manual_input
```

本单元自动适配器不得执行 `processing -> published`；完成结果统一进入 `needs_review`。数据模型仍保留未来
认证适配器的自动发布边界，但只有配置 `auto_publish`、适配器已认证、字段完整、关键置信度达标且没有阻断
警告时才允许该转换。

所有状态动作使用行锁和请求版本。状态冲突返回要求刷新，不能静默覆盖。归档只停止处理，不能删除媒体、
结果版本或历史。

## 10. Worker、租约与重试

### 10.1 领取与续租

- Worker 通过原子 SQL 领取一个兼容、可处理的 `queued` 任务。
- ERP 创建单调递增尝试，签发不可伪造租约令牌和 `lease_expires_at`。
- 首版租约固定 5 分钟；Worker 应在剩余时间不足 2 分钟时续租。
- 续租必须携带任务 ID、尝试编号、任务版本和原租约。
- 过期、被替换、状态变化或服务身份不匹配时续租/提交均拒绝。

### 10.2 媒体读取

Worker 只能读取当前租约绑定任务的媒体。ERP 签发短时、单次或有界次数的媒体票据；票据限定服务身份、
任务、尝试、媒体和到期时间，不能用于普通浏览器或其他任务。

### 10.3 结果提交

Worker 提交严格版本化结果：

- 契约、适配器、规则和结果模式版本。
- 结构化字段、每字段置信度、警告和缺失字段。
- 总分、等级、分项说明和建议。
- 安全耗时/资源摘要与幂等键。

ERP 在事务内验证租约、版本、结果模式、项目配置和数值边界，再保存结果版本并结束尝试。

### 10.4 重试

可重试错误包括临时网络、Worker 进程中断、Tesseract 超时和临时服务错误；使用退避重新进入 `queued`。
自动尝试最多 3 次。适配器不兼容、媒体永久无效、结果模式错误以及尝试耗尽进入 `manual_input` 或获权人员
归档，不返回伪造分数。

## 11. 适配器与评分结果

### 11.1 首版项目

- 英雄联盟：复用现有 MOBA OCR/评分函数。
- 无畏契约：复用现有 FPS/Valorant 评分函数。
- 和平精英：复用现有三图 OCR/评分函数。
- 其他项目：`manual_only`。

“复用”只指纯 OCR 解析和评分算法；不得复用旧上传路径、匿名身份、SQLite 记录或公开媒体 URL。

### 11.2 统一结果模式

所有项目输出：

- 0–100 总分和等级。
- 项目特定结构化字段与置信度。
- 分项名称、分项得分/权重和说明。
- 规则警告与严重级别。
- 面向学员的系统建议。
- 适配器、规则和模式版本。

原始指标必须保留为结构化字段，评分可重现。前端不重新计算分数。

### 11.3 认证和自动发布

分析配置继续允许管理员选择 `auto_publish | review_required`，但适配器还必须关联不可变的认证记录：黄金
样本清单摘要、验收时间、适配器/规则版本、验收者和允许项目。未认证版本即使配置为 `auto_publish` 也进入
审核并显示原因。

首版本单元的三个适配器全部标记为“本地试运行/未认证自动发布”。后续独立验收通过后才可创建认证记录，
不需要改写已有任务配置或历史结果。

## 12. 人工录入、审核、发布与修订

### 12.1 人工录入

人工项目、自动失败转人工、待匹配后选择人工以及整改/修订均使用严格项目结果表单。表单保存草稿，但只有
满足该任务配置的必填字段和 0–100 分边界后才能提交审核。

### 12.2 职责分离

- 上传截图不视为评价结果作者。
- 人工录入、修改 OCR 字段、调整分数或创建修订的人是该版本作者。
- 版本作者不能审核自己的版本，包括管理员。
- 审核页只允许通过或驳回，不能边审核边修改结果。
- 没有另一名获权审核人时任务留在公共队列，不自动发布。

### 12.3 审核

审核人查看去元数据预览、结构化字段、置信度、警告、分数、等级、分项和建议。驳回必须填写原因；原因只
进入受权业务历史，不进入审计元数据。驳回后由原作者或其他获权人员创建 `correction_pending` 版本。

### 12.4 发布与可见性

发布原子更新当前发布版本并记录审核/发布审计。学员本人和当前有效监护人只看到已发布版本。教练和其他
工作人员按报名服务历史、任务状态和对象范围查看；撤权或服务结束后原图权限按上游规格收回。

### 12.5 修订

已发布结果不能就地编辑。获权人员从当前版本创建 `revision_draft`，按原任务配置快照重新自动处理或人工
录入。新版本发布前旧版本仍为当前；发布后旧版本转为历史但继续可见和可追溯。

## 13. 页面设计

### 13.1 独立与内嵌评分页

保留评分工具现有首页、MOBA、FPS/和平精英和历史页面结构。独立与内嵌模式共用页面代码和 ERP 数据；
内嵌模式遵守现有同源代理和来源校验，手机端可全屏打开。

上传分步流程：

1. 选择获权学员/报名和项目。
2. 按项目槽位上传 1–3 张截图并预览。
3. 确认匹配信息和媒体摘要。
4. 提交任务并显示实时状态。
5. 查看已发布历史或需要本人处理的待匹配/整改任务。

无上传权限时页面保持只读，不隐藏获权的已发布历史。录像按钮禁用并明确提示 GPU 未就绪。

### 13.2 ERP 评价中心

- 评价首页显示可上传、处理中、待匹配、待人工录入、待审核、被驳回和已发布数量。
- 系统评价页继续提供内嵌和单独打开入口。
- 学员/家庭页复用多学员切换，只展示家庭范围已发布结果和获权上传入口。
- 教练/工作人员页按营期、项目、班级、学员、状态筛选任务和历史。
- 管理员页增加待匹配、失败、人工录入、公共审核、适配器认证和修订队列。

### 13.3 响应式和可访问性

- 桌面使用任务表格、筛选区和审核详情双栏。
- 手机使用单列任务卡、全屏上传/录入/审核页面。
- 关键操作有效触控区域至少 44×44 CSS 像素。
- 对话框/全屏页支持焦点进入、Escape/取消和焦点恢复。
- 页面不得出现横向溢出或被 ERP 移动底部导航遮挡。

## 14. API 与契约边界

具体路径在实施计划中冻结，但能力分为三组。

### 14.1 ERP 门户/管理 API

- 上传上下文、目标、槽位和窗口。
- 创建上传会话、提交媒体、确认并创建任务。
- 本人/家庭/工作人员任务列表、详情和已发布历史。
- 待匹配确认、人工草稿、提交审核、驳回整改和修订。
- 审核通过/驳回、管理员重新开放、归档和适配器认证。

全部使用现有 Cookie/CSRF、对象范围和私有禁止缓存边界。具体资源越权与不存在保持私有 404 等价；完全
没有能力时返回统一权限拒绝。

### 14.2 评分 Web v2 集成 API

评分 Web 使用服务身份加委派用户引用：

- 当前最小用户上下文和可上传目标。
- 上传会话/媒体转发与任务创建。
- 用户任务状态、已发布历史和获权人工操作。

服务身份不能扩大委派用户权限，每次请求都由 ERP 重新授权。

### 14.3 Worker v2 集成 API

- 领取兼容任务。
- 续租。
- 获取租约限定媒体票据。
- 提交结果。
- 报告可重试/永久失败。

Worker 不接受浏览器 Cookie，不提供普通人员查询、搜索或任意媒体读取。

### 14.4 契约版本

路径使用 `/integrations/evaluations/v2/*`，请求和响应包含契约版本、追踪 ID 和时间戳。ERP 与评分工具各保存
相同的冻结 JSON 样例和错误码清单。评分工具启动时报告支持的契约、适配器和结果模式；ERP 不向不兼容
Worker 派发任务。

## 15. 权限与隐私

复用并补齐上游权限：

- `evaluation_center.access`
- `evaluation_media.upload`
- `evaluation_media.original.read`
- `evaluation_jobs.match`：确认待匹配任务归属。
- `evaluation_jobs.manual_input`：创建或修改人工结果版本。
- `evaluation_jobs.review`
- `analysis_profiles.manage`
- `evaluation_adapters.certify`：认证允许自动发布的适配器/规则版本。
- `student_game_accounts.manage`

以上任务、媒体、配置和认证权限均为敏感权限，不混入全局 `evaluation_center.access`。管理员默认全局拥有；
主教练通过当前服务分配获得本人负责班级的人工录入和审核能力，仍受作者不可自审约束；其他工作人员必须
由管理员明确授予对象范围。待匹配确认和适配器认证默认仅管理员拥有，其他账号必须单独下发，且认证权限
不因拥有分析配置管理权限而自动获得。

权限支持营期、项目、班级、报名、学员和工作人员范围，显式拒绝优先。列表、详情、搜索、任务领取、媒体
读取和状态动作使用同一对象谓词。

禁止进入页面、公开错误、应用日志和审计元数据的内容：

- 图片或存储路径。
- 完整 OCR 原文。
- 手机号、身份证、完整游戏 ID。
- 系统建议、人工备注、驳回原因或修订原因原文。
- 无权候选学员或任务信息。

审计元数据仅允许安全 UUID、状态、版本、适配器/规则版本、格式、计数、结果和公开错误码。

## 16. 失败、错误与恢复

至少定义稳定错误类别：

- 上传窗口关闭。
- 上传范围拒绝。
- 媒体类型/大小/像素/解码失败。
- 业务重复任务。
- 待匹配或匹配冲突。
- 任务状态/版本冲突。
- 租约过期、租约不匹配和 Worker 不兼容。
- 结果模式/评分边界无效。
- 自审拒绝。
- 未认证自动发布拒绝。
- 媒体存储、审计或事务基础设施失败。

业务校验失败不得留下长期媒体、任务半行或成功审计。媒体事务失败要补偿已落盘对象；数据库/媒体/审计
基础设施失败不得伪造可重试业务结果。客户端根据稳定错误码展示安全提示，不解析异常字符串。

## 17. 并发与一致性

- 上传提交在一个受控事务中完成媒体归属、任务、配置快照和审计。
- 相同报名/项目/哈希并发创建只有一个任务成功，另一请求返回原任务或幂等冲突。
- Worker 领取使用 `FOR UPDATE SKIP LOCKED` 或等价原子迁移；一个尝试只能有一个活动租约。
- 结果提交锁定任务/尝试并校验版本；过期 Worker 不能覆盖新结果。
- 审核、驳回、归档和修订锁定任务/结果版本，竞争动作只有一个成功。
- 权限在列表与动作之间被撤销时，动作重新鉴权并失败；先前页面缓存不能作为授权依据。
- 文件落盘和数据库提交使用现有媒体事务补偿机制，不允许孤立长期对象。

## 18. 测试策略

### 18.1 ERP 纯规则和服务

- 中国时间上传窗口边界。
- 学员、监护人、工作人员、管理员和无权账号对象范围。
- 游戏 ID、主手机号、辅助手机号匹配顺序及零/多命中隐私。
- 文件槽位、数量、格式、大小、像素、解码和重复。
- 完整状态矩阵、人工转入、驳回整改、归档、发布和修订。
- 自审阻止、未认证自动发布和低置信强制审核。
- 幂等键相同/不同载荷行为。

### 18.2 PostgreSQL 与媒体

- 迁移升级/降级、约束、版本链和不可变边界。
- 并发任务创建、并发领取、租约续期/过期和重复结果。
- 审核/驳回/归档竞争，冲突后会话继续可用。
- 数据库、审计和文件失败的原子回滚/补偿。
- 权限撤销后的列表、详情、媒体和动作拒绝。

### 18.3 评分工具

- 英雄联盟、无畏契约、和平精英评分纯函数黄金输入。
- 使用合成或脱敏截图的 OCR 解析金样，不提交真实学员资料。
- Worker 领取、续租、幂等提交、重试、永久失败和重启恢复。
- 评分 Web 不读写 SQLite、不创建新 `uploads/`，浏览器不获得服务凭据。
- v2 契约与 ERP 冻结样例逐字段一致。

### 18.4 Web 与 E2E

- 独立打开登录返回原路径，ERP 内嵌无二次登录。
- 学员、监护人、教练、管理员上传和只读旅程。
- 自动处理、人工项目、待匹配、失败转人工、审核、驳回整改、发布和修订。
- 上传中/断网重试/重复提交不会创建重复任务。
- 1440、1024、768、360 四视口的触控、焦点、溢出和导航遮挡。
- 页面、响应、日志和审计中无 PII、存储路径或完整 OCR。

本地三服务门禁扩展为 ERP API/Web、评分 Web 和 Worker；真实 Tesseract OCR 可作为显式本地门禁，单元/E2E
必须仍有确定性的合成适配器路径，避免测试依赖不稳定的 OCR 环境。

## 19. 实施拆分建议

本聚焦单元适合在一个总计划内拆成以下独立任务流：

1. ERP 模型、迁移、权限和任务状态机。
2. ERP 上传会话、媒体归属、匹配和任务创建。
3. ERP Worker 租约、结果模式、重试和并发。
4. ERP 人工录入、审核、发布、修订和门户 API。
5. `game-score-tool` v2 Web 客户端与上传页面。
6. `game-score-tool` Worker、三个适配器和黄金测试。
7. ERP 响应式任务/审核/历史页面。
8. 两仓库契约、三服务四视口 E2E、文档和本地总门禁。

8 个任务流共享冻结契约但必须明确文件所有权；跨仓库变更分别提交，主任务在每个集成点做规格和质量复核。

## 20. 验收标准

1. 获权账号能在有效窗口上传 1–3 张安全截图，非青训营或无权账号不能创建任务。
2. 截图进入 ERP 私有媒体，评分工具不写新 SQLite/`uploads/` 正式数据。
3. 目标选择和游戏 ID/手机号匹配不泄露无权候选；多命中停在待匹配。
4. 英雄联盟、无畏契约、和平精英能通过 Worker 产生结构化 0–100 结果并进入审核。
5. 其他项目可人工录入并进入相同审核、发布和版本历史。
6. Worker 租约、3 次重试、过期提交和进程恢复均有确定行为。
7. 版本作者不能自审；审核通过、驳回整改和发布后修订均不可覆盖历史。
8. 学员/家庭只看到已发布版本，工作人员和管理员遵守对象范围与撤权。
9. 未认证适配器、低置信、缺字段和警告不能自动发布。
10. 两仓库契约、完整后端/Web 和四视口三服务 E2E 通过。
11. 旧评分数据/媒体、Docker/NAS、录像/GPU 和后续教学评价单元保持未触碰/延期。

## 21. 最终确认摘要

- 采用 ERP 编排、评分工具执行的双仓库架构。
- ERP 保存正式媒体归属、任务、租约、结果、审核、发布和版本。
- Worker 租约 5 分钟，最多自动尝试 3 次，失败转人工。
- 英雄联盟、无畏契约、和平精英首版自动计算但强制人工审核。
- 其他项目可上传并人工录入。
- 人工修改者不能审核自己的版本。
- 系统评价使用 0–100 分；日报/周报和结营问卷保持各自尺度。
- 管理员可配置发布模式，但自动发布受适配器认证和结果质量门禁约束。
- 旧 SQLite/媒体不迁移、不修改、不删除；Docker/NAS、录像/GPU 继续延期。
