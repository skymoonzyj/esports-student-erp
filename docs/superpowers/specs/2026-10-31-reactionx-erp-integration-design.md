# ReactionX 实体反应灯接入 ERP 规格

日期：2026-10-31。状态：规格确认，进入实施计划。用户已确认接入方向、“每人每项历史最佳入榜、本次成绩单独对照”，并接受自由手动控制只保留训练记录、不进公共排名。尚未实施或新增线上权限。

## 目标与已确认方向

在 ERP 天赋测试中使用实体反应灯，日常流程由网页管理，包括连接状态、学员选择、参数、开始与停止、成绩保存和查看。本地 Windows 连接器只负责设备通信、训练执行和待同步数据，ERP 是业务主记录。

天赋测评 1 的所有单项和新实体灯八种统一规则测试均纳入独立单项排行。每完成一个有效单项并保存，就展示本次成绩对应排名、个人最佳、当前前三名成绩及差距，不再要求先完成整套；实体灯自由手动模式只保存训练记录。

首次安装、唤起外部程序和配对由用户确认，不能静默安装。连接器主动建立经过验证的加密连接到 ERP，不向公网开放电脑端口。自动训练的逐次刺激由连接器调度，不逐次等待网页或服务器指令；网络往返不能计入反应时间。手动模式的明确点灯操作属于单独的训练交互，不作为自动反应测验。

## 接入方案

- 已选：网页管理加 Windows 连接器主动连接 ERP。可复用现有 BLE 与训练代码，网页使用同一账号及档案；代价是维护连接器安装包、命令与同步服务，并在真实 Windows 和灯具上验收。
- 未选：网页直接访问本机端口。会引入本地网络许可、跨域及本地服务攻击面，不作为初版备用通道。
- 未选：仅用 Web Bluetooth 重写。浏览器兼容和设备许可限制较多，也不能直接复用 Python 训练执行器。

排名方案已选择“每人每项历史最佳入榜，本次成绩单独对照”。没有选择把全部尝试直接排序，因为一人会重复占据前三；也不沿用“个人最佳整轮的各单项一起入榜”，因为它要求做完整套，且会遗漏其他轮中更好的单项。旧的整套综合排名继续保留自己的规则，新单项榜独立查询。

Windows URI 唤起与网页本地访问的约束参考 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/apps/develop/launch/handle-uri-activation) 和 [Chrome 文档](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access)。不通过关闭浏览器、系统或证书安全保护来实现接入。

## 入口与首次使用

入口检查的是当前网页已配对连接器的在线状态与兼容版本，不扫描电脑已安装软件清单，不以另一台电脑在线来表示本机可用。

未收到握手时显示“未检测到连接器”，分别提供启动、重新连接、下载安装和排障。不把“没启动、被阻止、未配对、版本不兼容、已离线”统一显示为未安装。

用户明确点击后，通过专用协议唤起已安装连接器；未安装时下载指定版本安装包并由用户自行确认安装。首次配对显示 ERP 站点、电脑与当前账号，完成后网页更新为已连接。默认不添加开机自启，不静默自更新；升级不得中断运行中的测试，须保留未确认上传的数据。

安装包不携带 GitHub 令牌、ERP 管理员密码或长期共享密钥。由 ERP 授权下载固定版本并核对摘要，不能把私有仓库访问凭据下发给浏览器。正式分发要求可信发布者签名；签名证书缺失时只能交付明确标注的内部测试包，不指导绕过系统安全警告。

## 配对与命令安全

复用 Python BLE 栈，增加无界面的连接器进程与必要的托盘状态、退出、配对确认及本地停止能力；不强制重新打开旧 Tk 主窗口才能执行。连接器仅主动访问明确配置且验证证书的 ERP HTTPS/WSS 地址，支持当前 HTTPS 18080 与后续经管理员确认的新站点。

网页登录凭据不放进外部启动 URL。配对采用短时一次性挑战、连接器生成的密钥以及两端确认，随后获得可撤销的最小范围设备凭证。URI 内容按不可信输入处理，不接受任意服务器地址、脚本、路径、BLE 字节或系统命令。凭证保存在当前 Windows 用户的系统保护存储中，不写普通日志。

设备身份与本轮参与者分开：至少保存服务器运行 ID、操作人账号 ID、被测人员 ID、连接器 ID 和本次设备映射；不以姓名或灯面编号作为唯一标识。设备硬件地址不出现在普通报告，日志不输出令牌或无关个人资料。

服务端在配对、列人、开始、继续控制、结果接收与读取时校验当前权限。新能力独立命名并复用现有权限范围解析和显式拒绝规则，不能借用 `talent_tests.take` 的 self 权限代他人测试。连接器没有浏览人员名单或任意选择被测人的权限。

首批超管可为自己或其有权查看并登记测试的有效人员档案发起现场试测；被测者不必已有激活账号，记录现场操作人与被测者，绝不创建账号或扩大被测者权限。普通报告读者仍按本人、有效监护或既有授权范围读取；权限撤销、停用和删除后拒绝新的读取或操控。

命令只包含明确白名单：扫描、连接、断开、识别、准备、开始、停止以及经模式校验的交互。每条有操作 ID、运行 ID、序号和有效期；重复请求返回已有状态，不重复启动。浏览器登出或换账号使控制租约失效；新账号必须重新建立自己的授权，不接管上一账号的测试或待上传队列。

## 训练执行与中断

单个连接器同一时刻仅执行一轮训练，设备组被该轮独占；扫描、识别、手动亮灯、其他标签页与其他操作员不得抢占正在测试的灯。顺序与基地模式的设备次序显式冻结，不能依赖 Python 集合或扫描发现顺序。

ERP 创建运行、确认操作人与被测者、冻结模式参数后，连接器确认设备已就绪，再本地倒计时和执行。启动按钮响应不代表灯已启动；网页分别显示准备、运行、停止处理中、待同步、已保存和失败。每次配置、模式或参与设备变化都需要新运行，不修改已完成记录。

设备计数、主机单调时间、服务端收件时间分别留存，不能互相替代。有效拍击时间只来自已识别协议的合法回执；超时、漏拍、误触不伪装成 0 毫秒有效反应。真假难辨平均时间只取正确拍击，同时保留正确、误触、漏拍、正确忽略及实际正确颜色比例。

手动控制保留网页点灯，但只在当前有效运行和设备租约内接受白名单动作，报告标为“手动训练记录”。计数器报告标为“计数训练记录”，主要展示次数和节奏；两者不能因为同样含设备计时字段而套用标准反应评价。设备识别、配对和调试点灯不生成训练成绩。

现有通知没有可靠的试次标识，单靠接收时间不能保证迟到回执归属。适配层必须为连接、运行和灯激活建立代际状态、去重与边界检查，并通过真实灯具确认可行的隔离方式。无法证明归属时标记该试次无效或本轮需复测，不能直接计入有效反应。设备重连时旧通知必须失效；无法解决的模式保留关闭。

断线、权限租约过期、连接器退出或设备异常时停止生成新刺激并尝试熄灯，倒计时和休息也必须可中断。网页只能在收到确认后显示“已停止”；关灯失败明确提示检查设备，并保留本地停止手段。网络断开时允许保全已发生的数据，但初版不支持继续离线开展新的测试，也不在恢复后自动重放启动或继续亮灯。

浏览器短暂切换标签不自动把整轮记录转移给其他人；刷新后可经当前授权读取同一运行状态。控制租约的续期、超时和失效检测采用有界机制，具体阈值由实施者结合 Windows 真机测试确定并记录，不允许无限等待或永久后台控制。

## 数据保存与报告

连接器在训练中逐事件持久化，运行结束生成不可变的待发送结果包；不再依赖窗口消费结束事件才落库。队列按 ERP 站点、操作人和运行隔离，加密或使用 Windows 用户级保护，不缓存身份证、联系方式、完整人员名单或网页登录密码。

服务端有运行唯一约束、操作幂等键、规范化内容摘要及事务提交。相同键同内容重试返回原回执，不同内容冲突拒绝；事件序号重复、非法模式参数、未知灯、跨人跨运行、缺事件、超范围时间和过期提交均不能静默接受。

只有服务端完成校验和持久化、返回匹配运行与结果 ID 的确认，网页才显示“已保存”。丢失确认时查询或重传同一包；已完整结束但尚未入库的测试允许原包补传，中断测试只能保存带中断原因的诊断记录，不能拼接为完整成绩。

登出或权限撤销不能把旧包改为新操作人补传。旧包留在原账号加密隔离区，页面明确显示待处理；原账号恢复合法授权或经超管专门核验后方可处理。超管核验不得改写被测者、原操作人或原始事件。设置有界的本地保留期和容量上限，达到限额时阻止新测试并提示，不能自动覆盖未确认的数据；具体容量和保留期在实施计划确定。

报告按模式保存原始指标、规则和连接器版本、协议版本、设备数、模式参数、质量状态与计时来源。只在这些比较条件一致时展示历史变化，设备布局、感应方式及测试目标也须作为条件记录；不与网页鼠标/触屏成绩混榜。统计和评价由服务端重新计算，不信任连接器提交的最终分数；这仍不等于认证硬件、防作弊或经过科学验证的人群常模。

首次仅接收新创建的 ERP 测试运行。旧桌面 SQLite 和 Excel 不自动导入；需要历史迁移时单独核对姓名对应、授权、数据完整度与版本。

## 独立单项排名与前三成绩

### 用户已确认的规则

适用范围为天赋测评 1 所有现行单项，以及新实体反应灯八种统一规则测试；手动控制保留训练记录，不进公共榜。不自动扩展到天赋测评 2，也不改变现有整套测评的评分或综合榜。每项有效成绩保存成功后即可查询排名，即使其余项目还未完成。中途退出、数据缺失、设备回执归属不明或影响该项可比性的质量异常记录保留原因，不伪装为有效参榜成绩。

同一数据库环境、同一可比组内，每名被测人员只以该项历史最好成绩占一个位置；按人员 ID 去重，不按账号、姓名、操作人或设备编号。未激活但合法建档的有效人员可由授权操作者代测并参榜。新成绩较差时不降低已有个人最佳，但本次成绩仍单独保存并展示对照。范围为累计有效成绩，没有另设日榜、月榜或每次发布重置。

榜单区域固定展示当前前三名成绩、本次成绩、个人最佳、参榜人数以及本次成绩与前三的差距。重新查看历史成绩时展示当前数据库排行，不暗示这是测试当时的历史名次。前三随新有效成绩、作废或规则变化更新，“一直显示前三”不是冻结最早三条记录。其他参榜者匿名展示，不增加查看其姓名、账号、联系方式、完整报告或档案的入口。

### 排名和差距的拟定细则

以下为随规格确定的技术细则，不把实施者拟定的排序和显示方法记作用户逐项指定。

- 天赋测评 1 延用该项既有服务端 0–100 评分，高分优先，不借新增榜单修改评分锚点、难度或旧原始成绩。评分相同则并列；原始毫秒、次数、等级等可作为额外展示，不能暗中成为未说明的评分或排名条件。
- “个人最佳排名”与“本次成绩对照排名”明确分开。本次对照名次为 `1 + 其他参榜人员中个人最佳严格优于本次成绩的人数`，排除本人更好的旧记录，分母仍为含本人在内的参榜人数；不会把自己当作另一名对手，也不把本次表现虚称为已刷新个人最佳。
- 并列采用现有竞争排名，如 `1、1、3`。前三展示按同一排序规则选出的三名不同人员，最多三行；同分用该最佳成绩的较早保存时间、内部稳定 ID 保证行次序，但不拆开并列名次。截断处仍有同分时提示并列人数；不足三人时只展示实际记录，不填虚拟成绩。
- 差距分别相对三行计算，明确标注“本次成绩”。天赋测评 1 首要展示评分差，如“落后 4 分／持平／领先 2 分”；可比原始指标可补充“慢 20 毫秒”等，不能以原始差距推翻同分并列。排名名次差和成绩差不得混称。自己进入前三时标注“本人最佳”，本次与本人最佳的差距仍有意义。
- 只能在该项规则、评分版本、引擎与输入方式等必要条件一致时比较；新单项分组只取本单项条件，不因为未完成的其他项目而拒绝参榜。鼠标、触屏等不能随意合榜，缺少必要比较信息的历史成绩显示具体未参榜原因。已保存的历史网页单项可在通过相同校验后查询参榜，不要求补测其余项目，不改写旧报告。
- 实体灯按模式及版本化的统一参数分榜，记录并核验灯数与次序、布局、感应方式、协议与计时来源、训练时长或次数、间隔及超时等条件。模式采用明确的原始指标排序，不硬造网页 0–100 分；具体比较元组、单位、精度、有效完成条件应逐模式写进实施计划并通过验收，不能由前端或客户端临时决定。
- 查询仅依据服务端已确认保存的数据；离线待同步显示“待同步，尚未入榜”，异常成绩显示未参榜原因。首次查询、保存成功、页面重新打开或回到前台时刷新；展示计算时间。请求失败显示不可用或带时间的旧值，不显示虚假的第 0 名或数据为零，不要求每秒推送。

### 实体手动模式的已确认边界

原有手动控制允许操作者自由选择目标及点灯时机，同样的模式名和设备数量不足以构成公平对照条件。不能直接将任意手动训练按平均反应时间混入公共榜，也不能悄悄删掉用户要求的该项排名。

用户接受自由手动控制保留训练记录、不进公共排名。结果页明确显示“手动训练不参与排名”，不虚构第 0 名。将来若增加固定脚本的手动测试版本，需另行确定时机、完成条件和可比规则，不把现有自由训练自动迁入该版本。

### 查询权限与一致性

查看目标人员本次与最佳排名前必须验证其结果读取权限；匿名前三对照不授权查询任意人员。服务端只返回当前授权结果、匿名前三必要指标、差距与聚合人数，不下发其他人的人员 ID、报告 ID、设备地址或内部排序键。试测、隔离环境和生产数据不混入同一榜；查询者权限失效即拒绝读取，作废成绩及被删除或停用的人员不继续作为有效榜单候选。无账号的合法档案不等于停用人员；既有账号均停用时排除该人员，不因普通岗位变化自动删除其有效历史成绩。

个人最佳、前三、对照名次和人数来自一致的数据快照。必须通过数据库过滤、按人去重及排序查询，并按查询分组和人员建立适当索引；不在一次请求中把全部历史成绩读入应用内排序。若使用派生表或缓存，须在新成绩、作废和资格变化后正确更新，且展示计算时间。具体表、索引、分页与查询方案由实施者在计划阶段核对现有模型后选择。

## 实施范围与验收

实施涉及 ERP 页面及后端、连接器通信与持久化、Windows 安装分发三个部分。ERP 延用 React/TypeScript、Python API、PostgreSQL、既有 A/B 主题和权限框架；连接器优先复用现有 Python/bleak，不因接入网页而重写为新语言。存储表、接口、迁移号与模块分拆由实施者在确认计划时按最新源码选择。

先完成协议和事件隔离，再完成配对、单灯闭环、持久化与幂等、网页流程，随后验证六灯和九模式。不能以单元测试、扫描成功或模拟回执替代实机验收。

验收至少覆盖：

- Windows 首装、重复安装、卸载、已安装未运行、拒绝唤起、配对过期、连接器版本过旧及站点迁移；无静默安装或任意协议启动执行。
- 两个账号、两个浏览器标签和两台电脑竞争控制；停用/撤权/登出、错误被测人、跨站重放及断线恢复；不得扩大已有业务权限。
- 单灯与六灯；每个模式的实际灯光、声音、传感、设备返回时间、主机超时；重复/迟到回执、编号相同的不同灯、识别灯与训练互斥、倒计时/休息/运行时停止。
- 事件中途崩溃、结束后崩溃、数据库提交后回执丢失、网络恢复重复补传、乱序事件和内容冲突；保存状态真实且不重复创建报告。
- 旧天赋测试 1/2 的目录、评分、权限、历史报告与原整套综合排名保持不变；新增独立单项榜不要求完成整套、不把单项最佳拼装成新综合成绩；实体测试完成状态与各模式开放标记准确。
- 单项保存即排名、同人重复测试不重复占榜、本次较差不覆盖最佳、无账号档案按人员去重、同分并列及第三行截断、零至三人、本人进入前三、不同输入/规则/实体配置隔离、差距正负方向正确、历史成绩当前排名、并发提交和重复回执无重行。
- 无权限不能查询他人成绩；前三响应不含其他人的身份字段；质量异常、作废、人员停用和缺失规则的成绩正确排除；待同步/查询失败不虚构排名；数据库大数据量查询不退化为应用全量排序。
- ERP 相关本地检查通过后只使用 `scripts/deploy-nas.sh` 发布；数据库迁移前备份和恢复验证不能绕过。Windows 连接器另行核验安装包来源、摘要、签名状态和实机行为，不把 NAS 发布成功当作 Windows 验收。
