# 房态统计口径与即时筛选

用户已确认展示口径，并补充“一切以左侧筛选为改变”，最后授权“直接实施”。本规格记录已确认需求及必要兼容规则，不再增加确认轮次。

## 目标与方案

采用“左侧基础筛选＋顶部独立快捷筛选”。后端在同一授权结果集内先应用基础筛选并统计，再应用快捷筛选、排序分页；不采用前端冻结旧数字或重复读取全量人员数据。左侧条件改变统计范围；顶部点击仅改变列表，不改左侧条件或其他数字。再次点击其他卡片替换前一个快捷条件。

## 统计

- 房间总数：基础筛选范围内全部登记房间，含问题、维修、停用、功能间。
- 已入住、当前入住：实际入住人数；已入住人员与待办理退房人员按现有实际住宿投影计数，不含未来预约。
- 空房：当前入住人数为零，且不属于 problem 问题房、maintenance 维修中、disabled 已停用的房间。统计、顶部空房列表及按空房快捷条件导出采用同一口径；单独的历史 API `occupancy=unoccupied` 仍表示物理无人入住，不改变旧调用语义。此项按用户后续纠正更新。
- 可入住：复用现有 is_assignable，包含有余位的部分入住和空房；仍须满足核对、保洁、父级启用、服务状态等条件。
- 不可入住：容量大于零且当前人数达到或超过容量的满房；功能间零容量不视为满房。
- 问题房：现有 problem 报障、maintenance 维修、disabled 停用三种服务状态的并集。
- 总床位、剩余床位、单/双/三人间、自定义房型：仅非功能间且不在上述三种问题状态的住宿房间。待核对、待保洁不删除物理床位，但仍禁止安排新入住。
- 入住率：上述床位集合内实际人数 / 总床位，零床位为 0.00%；当前入住总人数仍包含问题房内现住者，不因统计排除而隐去人员。
- 待核对、待保洁、功能间计数保留。各统计不是互斥分类，不强求可入住＋满房＝总房数。

## 交互

- 左侧楼栋、楼层、复选、性别、可入住性等选择立即应用；移除“应用筛选”。搜索保留原始输入，短延迟 250ms 请求，中文输入法组合完成再请求。
- 左侧改变时清除顶部快捷条件并回第一页；顶部切换保留所有左侧条件、替换快捷条件并回第一页。总房间卡清除快捷条件。
- 左侧“不可入住”选项与满房口径保持一致；旧 API unassignable 仍保留广义不可安排语义，新增 full 条件，旧调用和导出不被偷偷改义。
- 请求期间筛选控件不卸载；快捷切换时保留同一基础范围的统计。旧房间和可写操作在请求/权限复核时不得被当成当前可操作结果。
- 手机筛选即时生效，关闭仅关闭面板，不撤销已选条件；保留焦点管理、返回窗口筛选记忆、身份切换清理及权限变更隐藏行为。
- 选择跨页房间、批量确认等仍在查询条件改变时清除。现有导出默认范围须与当前基础＋快捷筛选一致，不忽略隐藏快捷条件。
- 导出窗口须显示继承的快捷筛选并允许单独清除或更换；历史导出的保洁状态与每日保洁条件也须可见、可清除。所有已选条件取交集，修改导出条件不改变房态页面筛选。

## 边界

只改统计、列表筛选和相关导出筛选兼容性；不改住宿记录、容量、权限、入住/预约/调房/退房规则。所有统计在授权过滤后计算。无数据库迁移。保留 dirty 工作区与既有功能；不提交或推送。通过本地验证后仅用 scripts/deploy-nas.sh 发布，SSH 端口 202。
