# ERP 云备份扫码授权设计

本规格面向 ERP 负责人和后续开发人员，定义在 ERP 内绑定网盘账号的流程。用户已确认先接入百度和 115，并使用自己申请的开发者应用；夸克保留现有实验性手动入口，本期不开放扫码。用户于 2026-10-06 确认本规格，下一阶段为实施计划审阅；不代表功能已开发或网盘已授权。

## 已确认的范围

- 入口位于超管的运维监控与云端备份页面，不是 ERP 账号扫码登录。
- ERP 负责授权流程、备份设置、调度、加密和校验；连接器只处理网盘适配与文件传输，不依赖飞牛。
- 使用用户自有百度和 115 开发者应用，不借用第三方应用标识，不经公共令牌中转服务。
- 保留现有 WebDAV 手动配置、本地完整备份和云端历史文件。
- 扫码成功、连接测试通过、已有可恢复云备份是不同状态，不得合并显示。
- 未配置自有应用或连接器时清楚提示原因，不显示假二维码或假成功。

## 现状和接入方式

当前 `OperationsCloudBackupPanel.tsx` 只有连接器账号、密码和目录配置；`cloud_router.py` 提供查询、保存、测试及复制。`erp_cloud_transport.py` 使用受控 WebDAV 传输，现有 API 没有网盘扫码或 OAuth 接口。私有连接器模板固定 OpenList 4.2.6、回环地址 127.0.0.1:5244，且不随 ERP 自动安装。

本规格建议新增 ERP 授权管理层，保留现有传输层。这比重写百度和 115 的整个大文件上传与恢复流程影响更小，也能保留已建立的完整性校验。另一个方案是直接嵌入连接器管理界面，但会暴露过宽的管理权限，且不能提供一致的 ERP 审计，因此不采用。

百度使用设备码授权，服务器取得官方二维码并等待手机确认。百度维护的 SDK 明确提供二维码地址、过期时间、轮询间隔，以及设备码换取令牌的流程。[设备码接口](https://github.com/baidu-netdisk/baidu-drive-sdk-go/blob/main/baidudriver/api/auth_device_code.go)、[令牌交换接口](https://github.com/baidu-netdisk/baidu-drive-sdk-go/blob/main/baidudriver/api/auth_device_token.go)

115 官方提供手机扫码 PKCE 授权：使用获批的自有 AppID 获取设备码和二维码，手机确认后使用校验材料换取令牌；该模式不要求 AppSecret。实现须遵守官方 URL-safe 编码、状态轮询和令牌交换要求，不能将连接器文档中“PKCE 尚未实现”的集成说明误认为平台不支持扫码。仍需以用户自有应用验证完整授权、刷新和可写驱动兼容性；验证前不开放正式使用，不以第三方应用或只读驱动替代。[115 官方扫码授权](https://open.115.com/doc/?file=/doc/115开放平台/接入指南/接入授权/手机扫码授权PKCE模式/获取设备码和二维码内容.md)、[115 驱动说明](https://doc.oplist.org/guide/drivers/115_open)

夸克 TV 的现成扫码驱动仅支持访问和下载，不能用于备份上传。夸克扫码不属于本期交付范围，也不影响现有实验性手动配置。[夸克驱动说明](https://doc.oplist.org/guide/drivers/quark)

## 页面操作

1. 超管在提供商卡片填写自有应用标识和需要的应用密钥。密钥只写入、不回显；留空保留原值，明确操作才能清除。未完成配置时显示缺少的条件。
2. 点击“扫码绑定”，由服务器创建短期授权会话。弹窗显示提供商、申请权限、二维码、有效期，以及取消和过期后重新获取的操作。
3. 手机确认后显示“授权成功，尚未启用备份”，展示厂商返回的账号昵称或脱敏标识。若无法可靠确认账号身份，不能自动切换旧账号。
4. 超管确认账号并选择专用备份目录。连接器用户名和密码由受控服务生成或沿用经验证的专用凭据，不要求把网盘登录密码填进 ERP。
5. 对候选账号和目录执行随机文件上传、完整回读和内容比对；仅清理本次生成的探测文件。通过后，超管确认“使用此账号与目录”，再按原有流程启用自动复制。
6. 只有完整加密备份上传、回读认证及完成标记校验通过，才显示“已验证云备份”；首次正式上线还需隔离恢复演练。

移动端同时提供官方授权页面入口，避免要求用户用同一台手机扫描自身屏幕。仅在厂商确实提供该入口时显示，不伪装成可用的扫码替代方式。二维码不会包含备份内容、ERP 会话 Cookie、恢复密钥或长期令牌。

## 状态与错误提示

授权会话使用独立状态：创建中、等待确认、授权成功待配置、配置中、待连接测试、测试通过待确认、已应用、已过期、已取消、失败。厂商没有提供“已扫码”状态时，不自行推断扫码状态。

等待扫码阶段的有效期取厂商有效期与 ERP 十分钟上限的较小值。授权成功后，目录选择、测试和确认进入独立的十分钟配置期限，不受已完成的二维码期限影响；超时仍未确认则取消候选，不因轮询自动续期。到期或取消后不能应用迟到结果，临时机密及时清除。刷新二维码会终止旧会话。

错误至少区分：应用未配置、连接器未安装或不可达、授权运行器离线、厂商不支持当前模式、二维码过期、用户拒绝、提供商限流、授权已失效、账号身份无法确认、目录无写入权限、读回校验失败、目标正在执行任务、配置版本已改变。只返回稳定错误代码和中文说明，不透传带令牌的 URL、响应正文或堆栈。

授权失效时停止该目标的新上传并提示重新绑定；本地备份与其他网盘继续运行。已有成功记录作为历史保留，但不能显示成当前账号的有效云副本。

## 服务边界与权限

沿用实际 `super_admin` 角色与全局 `operations.monitor.read` 双重校验。普通管理员和仅被追加该权限的其他角色均不能管理授权。写操作保留会话与 CSRF 校验；异步应用配置前重新检查操作者仍有效且仍有权限。

API 管理自有应用配置、授权会话、候选账号目录和应用确认。会话绑定发起人的 ERP 账号及登录会话；他人不能读取二维码或接管待完成授权。退出登录、账号切换和权限撤销后清理前端状态，后端拒绝继续操作。敏感响应使用 `no-store`，不进入持久浏览器存储、共享查询缓存、错误上报或分析埋点。

新增独立、短轮询的授权运行器，避免使用现有两分钟备份扫描周期等待二维码。它通过固定参数与标准输入调用私有桥接命令，领取有租约的任务，并与提供商和私有连接器通信。网页不访问服务器 localhost，不持有连接器管理令牌；API 容器不挂载 Docker socket。

授权运行器只处理允许的百度、115 操作和 ERP 管理的挂载；不提供任意 URL 请求、任意命令或通用连接器管理代理。提供商主机与接口使用固定白名单、TLS 校验、响应体大小和请求超时限制；拒绝非预期重定向。二维码图片通过受控代理或经校验的官方授权内容生成，不能使用用户传入的图片 URL 触发服务器请求。

二维码创建按操作者与提供商限流，每个提供商同时仅允许一个未结束的 ERP 授权会话。重复请求使用操作标识返回同一会话；轮询遵守厂商间隔和退避要求，不随浏览器数量倍增。任务租约、会话版本和目标版本共同阻止旧进程、重放请求或迟到回调应用凭据。

连接器需要的管理凭据仅存在于主机受保护的 secret 文件，前端不能设置管理端口或获取该凭据。部署时明确安装这一私有组件和授权运行器；不在用户点击按钮时自动安装软件。固定、测试过的连接器版本继续使用，不自动升级 latest。

## 保存凭据与账号切换

ERP 内应用密钥、设备码、PKCE 校验材料和候选令牌使用现有信封加密，并绑定提供商和记录标识。密钥不放在聊天、命令行参数、日志或审计元数据中。仅记录操作者、提供商、操作类型、时间和安全结果。

每次绑定先创建独立候选配置，使用单独的 ERP 管理挂载和目录受限的传输凭据验证，不直接覆盖工作中的挂载。当前备份继续使用旧配置；确认应用时短暂冻结该目标的新任务，等待现有任务结束，然后按版本校验切换 ERP 的配置引用。外部连接器操作不在长数据库事务内执行。

候选准备、测试、应用和清理都有持久操作记录与幂等标识。进程重启时先核对连接器实际状态，再继续或撤销候选。超时不能盲目创建第二个挂载，也不能用旧测试结果启用新目录。失败或取消仅清理本次 ERP 创建的候选对象，不修改手动挂载、其他网盘和远端历史文件。

初次扫码不自动接管已有手动目标；替换现有目标必须显示原账号与候选账号及目录差异，明确确认。旧配置保留为受保护的历史，不能误认作新账号上的可恢复副本。厂商可能限制同一应用的有效授权数量，新授权也可能令旧令牌失效；ERP 保留配置不等于能保证厂商旧授权继续有效，应显示风险并监控旧目标。

应用配置带版本。变更应用标识或密钥先影响新的授权会话，不偷偷修改当前挂载。令牌交付候选挂载后，其持续刷新即由连接器单独负责，无须等最终切换成功；ERP 不同时刷新同一令牌，也不把旧候选令牌再次写回连接器。交付过程通过幂等操作和状态核对确认，随后清除 ERP 中不再需要的临时令牌。

连接器数据目录可能持有明文厂商令牌，必须限制文件权限、禁止公网管理访问；不能宣称连接器天然具备 ERP 信封加密。ERP 管理的连接器恢复资料必须以一致性快照纳入受保护的加密备份，并纳入隔离恢复验证；不得直接上传未加密的连接器目录。独立备份恢复主密钥仍离线单独保存，不上传网盘。

厂商授权范围可能大于单个备份目录。页面应展示实际申请权限；ERP 限定备份目录不等于缩小了厂商授予的账号权限。解除绑定只停止 ERP 使用并清理对应受管凭据，不删除云端备份。若不能调用官方撤销接口，应明确提示还需在网盘官方页面撤销授权，不能声称已经撤销。

## 兼容与迁移

手动配置和扫码配置并存，原记录不自动转换、不自动授权或更换账号。新增授权数据和状态采用兼容迁移，不改已有备份包格式、完成标记规则、每日北京时间 03:00 本地备份或两分钟云复制扫描逻辑。

在 NAS 和普通 Linux 上均由 ERP 部署流程安装私有连接器配置与授权运行器，不调用 fnOS API。已有外置连接器默认只保留手动模式；只有运维明确登记为 ERP 可管理的实例后，才开放自动挂载操作。

迁移必须携带已验证加密备份、独立恢复主密钥、应用配置及受保护的连接器恢复资料。新服务器部署后重新检测授权、写入、回读和恢复能力；不能因旧状态为成功而跳过检查。

## 验收与开放条件

- 自动化覆盖实际超管与普通管理员边界、跨会话访问、CSRF、权限撤销、重复创建、并发确认、过期取消、迟到结果、限流退避、敏感数据不回显及缓存清理。
- 使用隔离连接器验证候选挂载权限、写入与回读、失败后旧配置不变、应用途中宕机恢复、任务互斥、令牌刷新后不被旧值覆盖；不连接真实用户目录进行破坏性测试。
- 浏览器覆盖电脑与手机宽度、扫码等待和过期、拒绝、刷新、账号切换、连接器离线和测试失败；模拟授权通过不能称为真实网盘可用。
- 每个提供商分别使用用户自有应用完成真实扫码、目录确认、写入回读、跨令牌刷新后的再次上传、完整加密备份回读及隔离恢复，全部通过才开放正式使用。
- 未取得应用资质或未完成提供商实测时，可交付明确“待配置／待验证”的界面，但不得将该提供商宣称为已完成接入。百度和 115 的开放状态独立。
- 产品代码完成且本地检查通过后，在主仓库执行 `scripts/deploy-nas.sh --source '/Users/skymoonzyj/.codex/worktrees/team-roles-divisions/new project3'` 发布；该路径是当前已核实的发布源，后续若工作树变化须先重新核实。发布预检查、健康检查或备份恢复失败都阻止宣布上线；不通过直接拷贝或临时 Docker 命令绕过。

## 用户需要提供的条件

用户在百度与 115 官方开放平台申请并取得自己的应用标识及必要权限。应用密钥届时通过受保护后台填写，不需要发给开发人员或贴在聊天中。开发者审批、应用资质和厂商限制由各平台决定，本文不保证审批时间。

本规格已确认，可据此编写实施计划；产品开发在计划审阅和执行方式确认后开始。实际安装连接器、填写应用信息和扫描授权均是后续明确可见的操作，不在规格与计划编写阶段执行。
