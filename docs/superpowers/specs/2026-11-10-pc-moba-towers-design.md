# 端游 MOBA 20 秒兵线与防御塔

用户明确要求：每 20 秒生成一波；双方各两座防御塔；塔伤害较高，也攻击玩家，并要求直接开始。按已说明的推荐实现路径继续，不重复等待规格批准。以下未由用户指定的数值均为工程默认，可按新版本调整。

## Scope / Approaches

在现有原创 Three.js 场景与固定 20ms 纯模拟中增加实际防御塔伤害，不另引入引擎或素材。只打小兵的训练塔方案被用户改为同时攻击玩家；完整可摧毁推塔/胜负模式不采用，以维持五分钟补刀评测。FPS、手机、权限和已有数据不变。

- 新规则 `pc-moba-v5`；v4 的 30 秒/50 兵/无塔/人物不受伤完全保留，旧快照序列化不得新增默认字段。
- v5 仍近战或远程任选、总时长 300000ms、试练最多 20 秒；从 0ms 开始每 20000ms 一波，15 波，最后 280000ms，300000ms 不再生成。双方每波 3 近战 + 2 远程，各 75 个小兵。
- 小兵和玩家攻击/移动参数沿用 v4；小兵继续只攻击敌方小兵，玩家只攻击敌兵，无技能、装备、反补、塔血量或摧塔。防御塔不可摧毁。
- 塔会攻击对方小兵与玩家。小兵/塔/玩家结果严格分开：塔和友兵击杀不计玩家补刀。分数 `HALF_UP(100 * last_hits / 75)`；仍存活小兵不记漏刀。玩家死亡无额外扣分，损失时间自然影响补刀。
- v5、v4、近战、远程使用冻结配置分别排名；旧已保存/未完成轮次与待保存练习可继续按原规则恢复。

## 冻结塔与人物默认值

逻辑场地仍 1000×562.5，相机/画布/小兵站位不变。四座塔固定且不参与小兵寻敌/单位分离或可攻击目标。

| ID | 阵营 | 位置 x,y |
| --- | --- | --- |
| ally-rear | ally | 70,162.5 |
| ally-front | ally | 280,400 |
| enemy-front | enemy | 720,162.5 |
| enemy-rear | enemy | 930,400 |

两方位置绕场地中心旋转对称。塔均：伤害180、攻击间隔1200ms、前摇300ms、范围240、弹速650。塔无移速、无生命条。阵营和前后塔外观可辨，使用原创代码模型。塔底部在道路侧旁；不得遮盖 HUD。

塔保持当前合法范围内目标直到死亡或离开范围；重新选敌时先选择范围内最近敌兵，没有敌兵才选敌方玩家，等距按稳定单位顺序。前摇时目标失效/离范围取消；已释放弹道继续追击原目标，离范围不撤销。不可击中友方；尸体不受伤；不同塔/小兵/玩家同帧伤害按稳定顺序处理，一次死亡只结算一次。塔 sourceOrder=10000+上述表格序号，小兵/玩家旧排序不变。

人物初始及复活位置(180,420)，生命1000，无自动回血。受伤只扣实际剩余生命（不累加过量伤害）；归零后死亡，5000ms 后安全区满血复活。五分钟计时、刷兵及战斗不停。死亡期间不移动、不攻击、不接收新指令，旧目的地/选敌/未释放前摇清空。此前已释放的玩家弹道可正常命中/补刀；攻向上一条生命的塔弹道不得伤害复活后的新生命。复活后不自动重放死亡期间的输入；需用户重新操作。到测试终点不补发复活/死亡/攻击事件。

HUD 显示真实生命、死亡次数和复活倒计时，保留波次/补刀/漏刀与整场倒计时。死亡不触发页面中断或停止时钟；失焦、窗口尺寸变化等原质量中断仍保留。

## 契约

使用独立 params/raw discriminator `lane_last_hit_towers`，不宽松修改 v4 的 `lane_last_hit`。

- `LaneTowerLastHitParams`：沿用 v4 同名共有参数但 kind为新值，wave_interval_ms=20000,wave_count=15；新增hero_health=1000,respawn_ms=5000,tower_damage=180,tower_interval_ms=1200,tower_windup_ms=300,tower_range=240,tower_projectile_speed=650,tower_positions（上述四座精确记录，id/team/x/y）；完整配置与JSON签名冻结。
- `LaneTowerLastHitRaw`：共有 deaths/attacks/cancelled_attacks，kind为新值；deaths unit_id 0..74，最多75，at_ms整型[0,300000)，每兵出生后才可死亡，按(at_ms,unit_id)严格排序且唯一，by_player严格布尔。
- 新增 `hero_death_times`：最多60个整型[0,300000)，严格递增，相邻至少5000ms；`hero_damage_taken`整型0..90000；无回血故须 `1000*death_count <= damage < 1000*(death_count+1)`。这些为一致性边界，不声称完整服务器战斗重放反作弊。
- 两种raw的攻击上限继续按固定攻击参数限制，玩家补刀不超过实际攻击次数，取消上限15000。不能使v4接受v5 ID/出生时间/统计字段。
- v5 score/report identity均pc-moba-v5；v4映射/完整序列化/已有排行榜资格严格不变。v5模式必填，其他套题拒绝，旧操作键重放先于新建校验。
- 服务端v5报告增加hero_deaths、hero_damage_taken；原补刀率分母仍实际死亡敌兵，总机会分母75，五段每分钟统计保持。报告建议可解释规避塔伤和死亡损失，不暗示职业能力常模。
- 前端统一 `isLaneTaskConfig(config)` type guard 支持v4+v5；现有v4 fixture JSON不得重写，新建v5 fixture/helper。精确历史版本与raw校验不能退化为仅kind判断。

## 代码接口与纯模拟边界

`LaneSimulation(mode, seed)` 保持旧v4；可增加第三个可选 `LaneTowerLastHitParams` 选择v5，未传时旧raw、快照、战斗行为不变。引擎只传服务端冻结参数，不从本地设置推导塔规则。`raw()` 可返回两种raw联合。不将Three/DOM放入模拟。

`LaneSceneState.wave_count`允许10|15；v5可选新增 `towers: readonly LaneTowerSnapshot[]` 与 `hero_status: {health,max_health,deaths,respawn_at_ms:number|null}`。`LaneTowerSnapshot={id,team,position,facing_rad,state:'idle'|'windup'|'attacking',attack_progress,target_id:string|null}`。projectiles可选kind:'tower'，旧弹道形状不加无用字段。现有单位数组始终包含hero，保证engine scene不崩溃。只有v5渲染四塔/人物状态。

可见单位几何优先点选、同深度稳定ID、失效目标不重选保持。塔不可作为攻击目标，但其实体挡住后方可选模型：命中塔返回null（地面移动），避免穿塔选敌。装饰底座/范围圈/粒子不参与命中。资源dispose、GPU尺寸缓存和场地可视范围维持。
