# 密码策略调整设计

## 目标

将 ERP 的新密码策略统一调整为 8–16 位，并要求至少包含一个大写字母、一个小写字母和一个数字，以便创建当前管理员账号，同时保持现有账号可正常登录。

## 适用范围

- 新建账号时生成或设置的密码。
- 用户修改密码、管理员重置密码时设置的新密码。
- 首位管理员 CLI 创建流程。
- 系统生成的临时密码。

已有密码哈希不做迁移。登录校验只验证哈希，不重新套用新策略，因此已经存在的旧密码继续可用；只有用户下一次修改或重置密码时才必须满足新策略。

## 规则

密码长度按 Python 字符数计算，必须满足 8–16（含边界）。字符集合要求：

- 至少一个 ASCII 大写字母 `A-Z`。
- 至少一个 ASCII 小写字母 `a-z`。
- 至少一个 ASCII 数字 `0-9`。

不强制要求符号。现有哈希算法和 Argon2 参数保持不变。

## 实现边界

密码策略继续集中在 `PasswordService`，所有创建、修改、重置和管理员 CLI 通过同一 `validate`/`hash` 入口。临时密码生成器改为生成 8–16 位且满足三类字符的值，避免现有 18 字节 URL-safe token 超过新的长度上限而无限重试。

前端登录页提示和 API 修改密码失败提示同步使用“8–16 位，包含大写、小写字母和数字”的文案。错误代码和数据库结构不变。

## 测试与验收

- 单元测试覆盖 8、16 位合法边界。
- 单元测试覆盖缺少大写、缺少小写、缺少数字、少于 8 位、超过 16 位的拒绝情况。
- 单元测试验证临时密码每次满足新规则且可被哈希。
- 现有登录、账号创建、密码修改和重置测试继续通过。
- 构建后在 NAS 上先验证管理员账号数仍为零，再用新策略创建首位 `admin` 账号；验证账号、角色和登录，不输出密码。

## 不做的事情

- 不强制已有账号修改密码。
- 不修改 Argon2 参数、会话策略或数据库模型。
- 不要求密码包含符号或特定语言字符。
