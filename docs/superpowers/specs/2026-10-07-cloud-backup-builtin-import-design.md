# ERP 云备份免填应用信息授权：补充规格

状态：业务流程、2026-10-09 协议兼容修订及实施计划均已由用户确认，实施中。本文件不是产品实现、真实网盘验收或 NAS 上线证明。

## 1. 目标与范围

超级管理员无需申请开发者应用、填写 AppKey 或 AppID，即可将百度、115 的授权结果导入 ERP，继续完成账号确认、备份目录验证和加密备份。备份由 ERP 管理，不依赖飞牛。

本文件补充 [原扫码授权规格](2026-10-06-cloud-backup-qr-authorization-design.md)。仅替换“默认必须使用自有应用、不得使用公共授权服务”的限制，增加显式的 OpenList 内置应用导入模式；原有超管权限、候选隔离、恢复校验等边界继续适用。自有应用作为高级选项保留，原有手动 WebDAV 配置保留。

本期不开发 ERP 自动接收第三方授权回调，不嵌入或代理网盘登录页，不抓取浏览器 Cookie，不借用其他软件的应用密钥，不增加夸克扫码或只读驱动。也不安装浏览器扩展、修改 OpenList 公共服务或改变 NAS 端口。

## 2. 接口依据与取舍

OpenList 内置应用网页授权不要求用户提供自己的应用信息，但当前已检查源码将授权结果返回其自身页面，没有供 ERP 自动接收结果的交接接口。115 的独立 QR 分支返回登录状态和 UID，不能把 UID 当作可上传的 Open API access token。因此采用用户明确确认的一次性复制导入，不在 ERP 显示虚构二维码或“自动绑定成功”。

依据：OpenList APIPages 源码固定版本 `581b57aa29594b34a7f99495f1d57ea4cb66c53a` 的 [百度授权](https://github.com/OpenListTeam/OpenList-APIPages/blob/581b57aa29594b34a7f99495f1d57ea4cb66c53a/src/driver/baiduyun_oa.ts)、[115 授权](https://github.com/OpenListTeam/OpenList-APIPages/blob/581b57aa29594b34a7f99495f1d57ea4cb66c53a/src/driver/115cloud_oa.ts)、[115 QR 分支](https://github.com/OpenListTeam/OpenList-APIPages/blob/581b57aa29594b34a7f99495f1d57ea4cb66c53a/src/driver/115cloud_qr.ts)。[115 接入文档](https://doc.oplist.org/guide/drivers/115_open)明确说明内置应用授权后复制访问令牌与刷新令牌，刷新无需用户 AppKey；[百度文档](https://doc.oplist.org/guide/drivers/baidu)说明内置模式使用在线服务续期。

三种路径的取舍：本期选用“内置应用 + 授权结果导入”；“自有应用 + ERP 直接扫码”保留为高级选项；“公共应用 + 自动回传 ERP”因没有已证实的交接协议而不实施。公开源码不等于公共服务在线行为或真实账号可用性已验收。

## 3. 页面流程

1. 运维监控 → 云端加密备份，百度和 115 的新绑定流程默认显示“免填应用信息”。已有目标继续显示其实际来源，不因新默认而修改。
2. 显示说明：使用 OpenList 提供的应用授权；第三方服务会处理网盘授权凭据，百度后续续期也依赖该服务。用户确认说明后，点击“打开授权页面”，在新标签页打开固定 `https://api.oplist.org/`，不携带 ERP Cookie、账号标识或任何令牌，使用 `noopener noreferrer`。
3. 页面给出网盘选择及“使用 OpenList 提供的参数”操作指引，应用信息留空。二维码或其他登录方式由外部授权页实际提供；ERP 不声称能控制其界面或获得扫码状态。密码只在网盘登录页面输入。
4. 授权后返回 ERP，分别复制访问令牌（Access Token）与刷新令牌（Refresh Token）到两个默认遮蔽的输入框。两项属于同一次首次绑定，不是每次备份都要填写。不接受整个网页、Cookie、UID、AppKey、回调 URL 或图片代替令牌。
5. 点击“验证授权”后创建异步验证任务；只显示安全状态，不回显凭据。切换到外部标签页再返回不能刷新掉当前 ERP 表单；关闭弹窗、退出登录或账号切换会清除输入。
6. 验证成功后展示由厂商接口取得的昵称或脱敏账号标识，提示“授权已验证，尚未启用备份”。用户确认账号、选择专用目录，沿用随机文件上传、完整回读和比对流程。
7. 目录验证通过后，用户明确确认应用候选配置。首次完整加密备份的上传、回读认证、完成标记及隔离恢复均通过后，才能标记为“已验证云备份”并开放自动复制。

高级设置继续提供已有自有应用配置与直接扫码流程。页面需区分“免填应用信息：外部授权后导入”和“自有应用：直接扫码”，不得让缺少 AppKey 阻止导入模式，也不得因导入模式存在而跳过自有应用校验。

## 4. 导入边界与状态

仅接受两个非空字符串令牌，每项最大 4096 字符；去掉首尾空白后拒绝内部空白和控制字符。请求体上限 16 KiB。使用显式 JSON 字段，不尝试解析任意 URL、Base64、HTML 或嵌套授权对象，不把输入解释为请求地址；验证只访问固定协议允许的接口。

新增导入流程为：等待粘贴 → 验证中 → 授权已验证 → 选择目录及测试 → 待确认应用 → 已应用。失败、取消、过期是独立结束状态。用户粘贴行为并不能证明已扫码或来自某个应用，必须由服务器验证。

导入会话自创建起 10 分钟内有效；验证成功后进入独立的 10 分钟配置期限。刷新页面、轮询和失败重试不能无限延长期限。每个提供商同时最多一个未结束的授权会话，两个模式共享此限制。

保留现有会话创建限流，新增导入提交每操作账号、每提供商每分钟最多 5 次，超限返回 429 和 Retry-After。重复提交使用同一个操作 UUID；同一会话、模式和相同凭据返回已有任务，不再次处理；相同 UUID 配不同凭据返回冲突。凭据一致性使用服务端带密钥 HMAC，不保存可离线猜测的明文散列。

校验错误只返回稳定错误码、字段名及中文说明，不能把 Pydantic 原始输入、响应正文、请求 URL、令牌前缀或异常对象回显到客户端或日志。

## 5. 验证、续期和凭据交接

私有授权运行器负责验证，不把厂商调用搬到浏览器，也不开放任意 HTTP 代理：

1. 使用访问令牌向所选提供商的固定身份接口查询账号；不信任用户输入的昵称、UID、模式标记或过期时间。
2. 记录刷新尝试的持久意图，再进行一次有界刷新。百度使用固定 OpenList 在线刷新配置；115 使用其官方令牌刷新协议。不得在公共服务间自动切换或允许网页填写刷新服务 URL。
3. 保存刷新响应提供的新令牌，再用新访问令牌核对账号一致。115 保存响应提供的真实有效期；百度内置刷新协议不返回有效期时，保存 `expires_at=null` 和明确的 `expiry_source=unreported`，界面只显示“到期时间未知”，不得编造有效期或显示“长期有效”。记录最近验证和刷新成功时间。账号不一致、刷新失败或返回了无效的有效期都不进入可应用状态；会话与配置期限始终由 ERP 的两个十分钟窗口限制。
4. 确认账号后，仅把最新凭据交付给一个隔离候选挂载。交付完成后，持续刷新由该 OpenList storage 单独负责，ERP 不再刷新同一凭据，也不把导入时的旧值重写回连接器。

刷新是可能轮换令牌的外部操作。发送后超时、进程中断或新凭据无法持久化时，进入“续期结果未确认”，不自动重试旧刷新令牌，也不凭相同任务重新刷新；提示重新取得授权结果。候选创建结果不明时沿用现有持久日志核对机制，不能重发旧令牌或盲目创建第二个 storage。

2026-10-09 协议兼容修订依据：固定版本的 [OpenList `pubRenew`](https://github.com/OpenListTeam/OpenList-APIPages/blob/581b57aa29594b34a7f99495f1d57ea4cb66c53a/src/shares/refresh.ts) 成功响应只包含访问令牌和刷新令牌，没有 `expires_in`。这一例外只适用于经确认的百度内置刷新协议；不放宽现有自有应用的 `TokenGrant`，也不允许任意提供商省略有效期。该修订随实施计划一起审阅。

授权成功与刷新成功均不等于有上传权限，仍需目录写入、回读、刷新后的再次上传以及完整备份恢复验证。网络不可达、限流和已撤销授权分别显示；失败不触发隐藏的自有应用或第三方服务回退。

## 6. 权限、隐私与旧账号保护

- 继续要求实际 `super_admin` 角色与全局 `operations.monitor.read` 权限；会话绑定操作者账号和 ERP 登录会话，写入保持 CSRF 防护，任务应用前重验权限。
- 导入令牌仅通过同源受保护 POST body 进入 API，在临时记录内按提供商、记录与模式绑定信封加密。敏感对象不参与 repr，不进入日志、审计元数据、错误追踪、浏览器持久存储或共享查询缓存。
- 输入不自动完成，不自动读取剪贴板；被服务器确认接收后立即清除输入及不再需要的前端引用。网络结果未知时先按操作 UUID 查询原任务，不自动发起第二次验证。所有敏感响应 no-store。
- 成功交接、失败、过期及取消后清理不再需要的临时凭据；用于幂等查询的安全任务状态保留。退出、账号切换、权限撤销后清除前端秘密，拒绝继续处理迟到结果。
- 不修改旧目标直到新候选经身份确认、当前版本检查、目录读回和原有任务排空后被显式应用。失败仅清理本次受管候选，不删云端历史文件或其他挂载。
- 页面要求使用新取得、未被其他挂载消费的授权结果，禁止从当前活跃 storage 导出凭据再导入。若识别到同一受管授权的重复令牌，在刷新前拒绝。即使 ERP 旧配置不变，新授权次数限制或复用同一刷新链仍可能令厂商侧旧授权失效；不能承诺失败绝不影响旧授权。
- OpenList 及公共授权服务可接触网盘令牌；ERP 本地信封加密不能消除此信任关系。连接器数据继续纳入加密冷快照与恢复验证，恢复主密钥单独离线保存，不上传网盘。

## 7. 模式、迁移与组件边界

模式明确为 `own_app` 和 `openlist_builtin_import`。新界面显式选择后者；兼容旧客户端的未传模式请求仍解释为 `own_app`。所有已有授权会话、操作、候选及恢复记录保持或明确补全为 `own_app`，不得把历史数据回填为新默认。

自有应用表保留。导入会话不再无条件依赖自有应用记录，但仍校验提供商枚举；通过新增迁移扩展关联与约束，不修改已发布迁移 `0063_cloud_authorization`。

每次会话冻结模式及版本化的授权/刷新配置标识；操作、候选、私有 RPC 和恢复日志携带一致来源。自有应用校验原应用修订，内置导入校验固定授权配置修订，不能用伪造 configured=true 或无约束版本零跳过检查。幂等指纹包含模式与配置修订。

百度候选根据冻结模式显式选择在线刷新或自有应用直接刷新；不根据 AppKey 为空来猜测。115 采用相应经过验证的 Open API storage 配置。解绑、清理及灾难恢复使用原候选的来源，不使用页面当前默认值；恢复旧日志时仅在确认其原版本的情况下解释为 own_app。

2026-10-10 最终恢复边界修订：正常同库进程重启仍按持久刷新检查点续作；完整备份还原会回滚数据库历史，却不能回滚厂商在备份之后消耗的令牌。认证的新主机交接必须持久化恢复专用意图，并在释放原 exact 维护 fence 的同一事务内关闭所有未完成的内置导入（含尚未发送、refreshed、verified 及已交付未应用），要求重新授权。保留已应用活动目标、原自有应用/手动配置、云文件和受保护候选清理日志；未知来源或校验失败保留 gate。丢失释放应答后的无 gate 重试只读确认，不失效随后创建的新授权；遇到新 gate 则拒绝。备份和正常重启不调用这一恢复专用失效动作。

主要职责沿用现有边界：

- `apps/web/src/operations/`：模式入口、外部授权指引、只写输入、任务和结果展示。
- `apps/api/app/operations/cloud_auth_*`：严格契约、模式/权限/幂等/租约约束、加密记录和状态转换。
- `scripts/erp-cloud-authorize.py` 与 `scripts/cloud_auth/`：固定协议验证、刷新发送边界、候选交接、恢复与清理。
- 新迁移和备份恢复契约：兼容历史 own_app 数据与受管连接器快照。

不改变每日北京时间 03:00 本地备份、两分钟云复制调度、加密归档和完成标记格式。编辑高级设置或选择模式本身不切换备份账号、不自动启用任何云目标。

## 8. 验收与发布条件

自动化至少覆盖：

- 无自有应用时可开始导入；原自有应用入口仍按原权限及配置工作；旧请求和旧历史不被新默认改变。
- 非超管、跨登录会话、CSRF、权限撤销、过期、取消及迟到任务被拒绝。
- 空值、超长、控制字符、误粘贴 URL/UID、错网盘凭据、错误响应全程不泄露输入。
- 同操作重复提交只执行一次验证；不同凭据冲突；并发双模式仍只有一个会话；限流有明确中文说明。
- 刷新前后身份一致性、结果未确认不重试、崩溃后不重投递旧令牌、候选接管后的唯一刷新所有权。
- 失败不应用目标，旧候选模式的解绑/清理/恢复不受新默认影响；新迁移保留已有数据。
- 电脑和手机布局、切出取授权结果再返回不重置表单、提交及退出后清理秘密、外部服务不可用及授权失效提示。

每个网盘独立完成真实账号授权、身份核对、目录写读、跨刷新后的上传、完整加密备份回读及隔离恢复，才可宣称该提供商已可用。模拟测试、导入成功或 NAS 健康检查不能替代这些验收。尚未真实验证时仅供超管绑定验收，保持自动复制关闭；夸克状态不变。
