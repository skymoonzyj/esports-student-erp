# 天赋测试 2：端游 FPS 可选全屏

状态：用户已在对话中确认以下小改动方案及实施计划，开始实施。

## 目标与范围

端游 FPS 的项目准备页提供“进入全屏／退出全屏”，试练和正式测试共用，保留窗口模式。仅改变展示容器，不改变玩法、计时、评分、排名、权限或数据库，不自动修改旧轮次。

## 方案选择

- 已选：独立全屏按钮，先完成全屏切换，再单独开始测试。切换与鼠标锁定、服务端尝试创建分开，失败时仍能使用窗口模式。
- 不采用：强制全屏或将全屏请求合并到开始测试按钮；这不符合“可选择”的需求，也增加启动失败处理的复杂度。

## 行为约定

- 只对端游 FPS 显示入口；手游及 MOBA 保持原样。
- 全屏目标为测试容器，ERP 导航不进入全屏画面。场地维持 16:9 等比放大，非 16:9 屏幕留边，不拉伸、不裁切；不改变鼠标灵敏度和视野参数。
- 进入或退出全屏不自动开始、保存、放弃任何尝试。全屏请求失败时显示中文提示，不创建服务端尝试，也不自动重复申请。
- 全屏过渡完成且尺寸稳定后才允许开始；试练、启动、倒计时、正式计时中不能通过按钮切换显示模式。
- 浏览器原生 Esc 保持可用：退出鼠标锁定、退出全屏或实际场地尺寸变化，都沿用现有中断处理，当前未完成项不得续接计时或提交残缺成绩；已保存项目不受影响。
- 项目退出或卸载时仅清理自身全屏和事件监听，不退出其他元素的全屏，不让延迟回调作用到新账号或新项目。
- 不支持全屏的浏览器保留窗口测试，并明确说明。全屏前后都保留真实环境尺寸采集和原有设备检查。

## 开发选择与验收

开发选择：复用现有 React 测试容器与浏览器原生 Fullscreen API，不新增依赖；保持 pc-fps-v4 和旧版规则不变。准备页的说明、设置和结果允许滚动，但实际测试场地和计时信息必须同时可见。

验收包括全屏进入/退出、原生 Esc 中断、请求失败、异步卸载清理、窗口回归、三项全屏试练与正式保存路径。真实鼠标锁定和全屏必须通过真实浏览器验证，不能用模拟事件冒充。生产仅做只读发布核验，不生成测试成绩。

本地检查与独立复核通过后，必须使用 scripts/deploy-nas.sh 发布，并核验活动版本、健康及脚本要求的备份恢复；失败时不得声称发布完成。
