当前四个套系仅向实际有效的超级管理员开放试测，其他账号仍未开放：

2026-09-22 用户确认使用现有超管账号直接验收，不建立测试账号或独立网站。超管从“天赋评测 2”选择标有“超管试测”的套系，正式完成四项后生成本人报告，练习记录独立保存。报告遵循原有查看权限，会出现在获权报告列表中，不冒充学员成绩。预览仍要求本人有效 take/read 权限，显式拒绝、账号停用和角色撤销均不能绕过；设备、计时、计分、保存和恢复限制不变。

## 四个套系与玩法

### 听声辨位试听预览

模块首页提供“听声辨位（试听）”新页面入口。预览仅允许当前有效超级管理员且具有本人 take/read 权限的账号使用；每个 HTML、样式和脚本请求都由服务端重新核验权限并禁止缓存，普通管理员和其他角色不能通过复制链接加载试听资源。

试听先检查左右声道与舒适音量，再完成八个水平方向的判断。页面显示正确率和平均角度偏差，允许作答前重听；结果仅在本页内存中显示，刷新或关闭后清空。试听不创建正式轮次、练习记录或报告，不改变现有四项配置。NAS 使用现有 HTTPS 18080 端口提供预览。真实耳机与手机效果由超管验收，验收通过后是否向其他账号开放另行确定。

四套目录和成绩彼此独立。共享引擎或相似玩法不表示不同设备、套系或输入配置的结果可以直接比较。

| 套系 | 四项玩法 | 主要控制与设备边界 |
| --- | --- | --- |
| 端游 FPS | 精准定位与微调、持续跟枪、多目标切换、敌我识别 | 鼠标相对位移瞄准，左键射击；正式运行需要 Pointer Lock 和 WebGL2 |
| 手游 FPS | 精准定位与微调、持续跟枪、多目标切换、移动与射击协同 | 触屏瞄准、屏幕开火按钮，协同项使用虚拟摇杆；支持多指 |
| 端游 MOBA | 补刀时机、走 A 节奏、危险区域识别与躲避（v3）、小地图注意力 | v2/v3 补刀、走砍、躲避可用左键或右键单击移动／攻击；小地图项目使用左键直接点选 |
| 手游 MOBA | 危险区域识别与躲避（v3）、技能方向控制、移动与攻击协同、小地图注意力 | 虚拟摇杆、攻击按钮、可拖拽技能按钮和小地图触控；支持多指 |

场景使用原创几何目标、角色、弹道和地图，不使用商业游戏素材，也不在运行时拉取外站模型或纹理。每项正式运行和练习均为连续 60 秒；输入有效区间为 `[0, 60000ms)`，不能暂停后拼接成绩。

### FPS 屏内刷新与旧规则（v2）

端游与手游 FPS 均保留原来的转动视角操作。精准定位、目标切换、敌我识别在每个新目标／新靶组生成的时刻，以当时的相机视角和实际测试区域宽高比计算位置；完整靶标必须在画面内，不能只让靶心可见。靶组中的两个目标同时满足可见和俯仰可达条件。出现之后的位置固定，不随准星移动，也不因主动转开视角而自动拉回。

手游移动射击的新目标使用每轮开始时的玩家位置、朝向和俯仰；地面检查点与移动规则不变。持续跟枪是一条连续的移动路径，不会逐轮刷新，本次不改变其路径和速度。机会数、目标大小、角距离档位、计时和评分公式不变；随机位置在模拟时间边界生成，读取画面或改变渲染帧率不会重新随机。

以上为 v2 规则；v1/v2 正式轮次、尝试、页面试练和待保存结果继续使用创建时冻结的配置。旧轮次会提示规则差异：可完成本轮后新建，或明确放弃后新建；放弃保留已保存项目，但本轮不再生成报告。旧成绩不重算，新旧规则不计算进步差值，旧“天赋测试”不受影响。

### 测量修正版（v3）

2026-09-23 修正版完成验收并发布后，新建四套正式轮次及自由练习使用各自 `<suite>-v3` 目录和引擎；是否已上线以同日验证记录及 NAS 发布回执为准。以下五项采用新的评分／报告 v2，其余十一项保持 v2 参数和玩法及原评分／报告 v1。新旧结果不能直接比较，不自动升级进行中的轮次。

- 双端多目标切换：每项 20 组，每组 3 秒。开始仅显示第一靶，命中后才生成第二靶；第二靶耗时从第一靶命中开始计算。首次获取与真实切换耗时分开展示。每个新目标都在生成时当前视野内，生成后固定世界位置。
- 手游移动射击：每项 20 轮，每轮 3 秒。只有实际水平速度至少 1 m/s 连续达到 100 ms 后的命中才有效，满速为 2 m/s。停止、低速及新轮次会重置累计；原地射击后再走动不算联合成功。资格由引擎测量，页面只显示反馈。
- 双端躲避：每项 30 轮，每轮 2 秒。根据黄色预警进入当前安全圆，在红色爆发期间持续保持完整安全；爆发期间短暂离开也会失败。安全圆逻辑半径 32，玩家半径 12，玩家中心距安全圆中心至多 20 才完全安全。正式 PC 预警 1000 ms、手机 1100 ms，爆发 150 ms。报告解释安全区进入用时，不再把首次移动用时称为躲避反应。
- 新版缺少成功样本的耗时指标显示“—”，不伪造 0 ms；旧报告标签、空样本显示及保存快照保持原样。

分数仍是内部试行分档，不是人群常模、职业潜力结论或反作弊认证。纯引擎自动策略与帧率回归不替代真实设备验收。

## 正式测试与自由练习

### MOBA 操作与任务反馈（v2）

以下说明 v2 操作基础；v3 保留未改项目的操作和反馈，躲避项目改用上文安全区规则。既有 v1/v2 轮次、尝试和待保存结果沿用冻结配置。旧成绩不重算，新旧版本不计算进步差值。旧轮次在项目列表及准备阶段说明差异，用户可完成后新建，或主动放弃后新建，不自动放弃。

- 每项在准备画面说明测试目的、具体控制、操作示例、成功条件和真实计分方式。这些是基础操作训练，不冒充完整对线、团战决策或职业潜力判断。
- 补刀仍按攻击生效时间落入固定窗口判断；提前显示正确点击时机、自动补刀、改变血量轨迹均不属于本次修改。
- 走砍／移动攻击仍只要求同一轮完成攻击且在本轮结束时到位，不强制动作顺序。“先完成出手，再移动”是建议而非新增计分条件。前摇中移动会取消攻击，页面显示出手、完成、取消及到位结果。
- 旧 v2 躲避仍按是否受击计分；连续移动有效。旧指标“每轮首次移动平均用时”不是纯反应能力分数，v3 改用安全区进入用时。
- 手机技能瞄准 v2 的蓝色虚线表示自己的释放方向，敌方黄色预警保持区分；实际命中才计分。重复的已消费释放手势不能把已命中反馈改写为失败。
- 小地图是主目标与地图提示的双任务。直接点主目标与提示象限，错误选择和无提示点击会减少有效响应；手机 v2 不显示无效攻击按钮或多余摇杆。旧 v1 控件与操作保留。
- v2 反馈只展示已发生的状态／结果，不泄漏后续随机目标、时机或正确答案。PC 的左键等价操作不改变小地图原本的左键语义，右键仍可使用。

### 测试中的离开保护

应用内后退、路由跳转时，对正在试练／启动／倒计时／运行或待保存的测试弹出确认。弹窗不会暂停业务时钟；继续测试保留当前页面，确认退出等待启动中的请求确定身份后结束未完成尝试。中断失败时保留页面供重试，权限已经撤销且没有待保留结果时仍允许返回入口。

完整且可持久化的待保存结果在确认离开后仍保留，可以回到本项对账重试；仅存在当前页面的结果不被静默丢弃。最后一项保存成功的报告跳转不被误拦。原生刷新／关闭页只使用浏览器离开提醒，无法保证关闭过程中完成服务器请求，仍按既有恢复／超时机制处理。

PC MOBA 场景内抑制可取消的右键菜单、非主键默认动作与前进后退侧键，不影响场景外页面。浏览器内置、扩展或系统级不可取消的导航手势不能保证由网页完全禁用；若右键拖动会返回，可改用左键，或关闭该浏览器的鼠标手势。

正式流程为：选择套系和项目 → 设备检查与操作设置 → 最多 20 秒的不计分本地试练 → 3 秒倒计时 → 60 秒正式运行 → 服务端保存确认。试练可以提前结束或重做，不写练习记录，也不增加正式进度。只有服务端确认保存的单项结果才计入四项进度；四项全部确认后才生成该套系的正式报告，不计算跨套系总天赋分。新增内部排名可使用同套系四项均分，但不把它解释为总天赋分。

正式单项由服务端按冻结规则输出 0—100 整数分，舍入采用 `ROUND_HALF_UP`。档位固定为：

- 0—39：较低表现
- 40—69：中等表现
- 70—89：较高表现
- 90—100：超高表现

这些分数和档位是内部训练规则，只描述本次场景、输入设备和操作条件下的表现，不是人群常模、医学或智力结论、职业潜力评级、防作弊认证或商业游戏段位。页面不提供跨套系平均分、全球排名或官方百分位。

自由练习可选择 1—5 级难度，默认 3 级。练习完成后只保存原始指标、难度、设置、环境和版本，不生成正式 0—100 分、档位、正式进度或四项报告，也不进入正式历史比较基线。同套系、同项目、同难度且规则、设置、环境和质量状态一致时，用户可以显式选择当前页两条本人练习记录比较原始指标差值；页面不据此给出进步百分比或优劣结论。

### 数据库内部排名

2026-10-05 确认新增综合及单项排名。四个套系分别排名，不与天赋测试 1 混榜；冻结规则/引擎版本及逐项输入类型不同的成绩也分组，PC FPS 的 raw/relative 鼠标输入分属不同输入子类型。屏幕尺寸、灵敏度等不逐一划为新榜，因此名次仅是内部训练参考，不代表相同硬件条件、全球排名、官方百分位或职业适合度。

仅完整且无质量警告的正式轮次参与，每人在同组中采用均分最高的一整轮；均分相同则选较早完成的轮次，再按稳定报告编号确定。所有单项排名也使用这个被选定的整轮数据，不拼接历次单项最高分。同分并列，例如第 1、1、3 名。练习、未完成或需复测的成绩以及不留存的听声辨位试听不参与；已保存的超管正式试测与其他正式成绩遵循相同规则，不按当前角色追溯删除成绩。

排名在数据库查询时实时计算，显示“第 X 名／共 Y 人”。打开历史有效报告时会标明当前同组最好整轮及其报告入口，原报告快照不变；不符合条件的报告显示不参与原因。接口沿用报告权限，仅返回所查看人员的最好成绩/名次及汇总人数，不提供其他参测者的身份、报告或成绩名单。

## 设备与质量限制

- PC 场景最低可用区域为 800×450 CSS px；手机场景最低为 560×280 CSS px，并要求真手机提示、触屏能力、横屏和实际触摸输入。
- PC FPS 若不支持或未保持 Pointer Lock，不能开始或继续正式计时；WebGL2 不可用时不降级成另一种同名计分玩法。原始鼠标模式不可用时可使用普通相对鼠标，但会记录不同输入配置。
- 手机方向锁定和全屏只是浏览器允许时的增强，用户仍需能手动转为横屏。首版不支持平板、手写笔、陀螺仪、手柄、键鼠映射或自动开火作为正式验收输入。
- 横竖屏切换、实际游戏区域几何变化、失焦、后台切换、丢失 Pointer Lock、触点取消或 WebGL 上下文丢失，会中断当前未保存项；恢复页面后不会自动补算或自动发射。
- 单次帧间隙超过 500 ms 会中断本项。大于 50 ms 的帧间隙累计超过 3000 ms，或出现混合／未确认输入时，协议有效结果保留但标记“需复测”。
- 不采集硬件序列号，不建立设备指纹。网页灵敏度、输入延迟和刷新率记录不是硬件校准值，也不能宣传为商业游戏中的相同灵敏度或物理 DPI。

真实 iPhone Safari 和 Android Chrome 的横屏、多指、安全区、后台／来电切换、取消手势、完整 60 秒保存和报告流程尚未完成验收，因此两个手机套系暂不向非超管账号开放，由超管使用真手机试测。桌面浏览器能力也必须以规定设备矩阵的实际结果为准，单元测试或模拟触摸不能替代这些证据。

## 中断、保存与恢复

设备检查、设置和试练完成后才申请运行尝试。运行占用最长 90 秒，用于 3 秒倒计时、60 秒操作和启动网络开销；它不是延长作答时间。正式和练习首次提交必须在服务端创建尝试至少 63 秒后、创建后 30 分钟之前；早到返回 `409 esports_result_too_early`，不会写成绩、报告或成功审计，也不消耗原提交操作键。这个下限同样适用于旧版尚未保存的尝试，不能用浏览器时钟快进绕过。

90 秒运行占用结束后仍可在 30 分钟提交窗口内恢复已完整生成的原结果，但不能续跑。已经保存成功的同账号、同尝试、同操作键和同内容请求，在当前授权有效时可以超过窗口重放原结果，不会重新计分；恰好 30 分钟不能首次提交。

创建、提交、放弃和中断都使用稳定操作键。结果保存失败时，应先用原尝试和原操作键与服务器对账，再决定重试；不得创建第二份结果。当前浏览器只在 `sessionStorage` 中保存提交所需的结构化 pending 数据和操作键，最长 24 小时，不保存令牌、逐帧输入、鼠标轨迹、录屏、联系方式或身份号码。退出登录、切换账号、确认保存或过期后会清理对应缓存。

刷新、换页或本地缓存丢失后，恢复页先查询服务器：已经保存则展示结果；仍有本账号完整 pending 时按原键提交；没有完整结果时，用户只能结束未完成尝试后重新开始。离开、刷新、失焦或设备变化造成的当前未保存项需要重做，但同一正式轮次中其他已保存项目继续保留。

## 权限与隐私

- `esports_assessments.take`：仅支持本人正式测试和练习的 `self` 范围。
- `esports_assessments.read`：支持 `self`、`family`、`assigned_class`、`person` 和 `global` 范围。
- 参加测试必须同时具有本人有效的 take 与 read；显式拒绝优先。旧 `talent_tests` 权限、人员查看权限、管理员／教练／监护人身份不会自动授予新模块权限。
- 练习、进行中正式轮次和中断状态只允许本人及具有 global read 的实际超管查看。其他获权读者只能看到服务端按当前关系和范围过滤后的已完成正式报告。
- 列表必须先按授权范围过滤，再分页和计数。越权对象和不存在对象统一返回私有 404，不泄漏人员是否存在；权限撤销后不能继续读取旧缓存中的私人记录。

前端菜单和按钮只是能力提示，不能替代服务端授权。正式报告显示四项各自的原始指标、单位、服务器分数、档位、冻结规则／设置／环境和质量提示，不展示手机号、身份证号、逐帧数据或输入轨迹。

## 发布边界

本页记录产品和运行边界，不是测试成功、真机通过、生产部署或开放运营的凭证。超管试测是上述用户确认的有限预览，不代表普通用户正式开放。只有规定的接口、输入、报告、浏览器／真实设备矩阵、恢复与发布检查全部通过，且前后端开放集合一致时，才可把相应套系向其他角色开放。部分套系通过时必须逐项说明，不能写成四套全部完成。

NAS 正式发布必须使用仓库规定的 `scripts/deploy-nas.sh --source <已审核发布源>` 流程，保留预检、数据库备份、迁移、健康检查和隔离恢复验证；不能用手工复制或临时 Docker 命令绕过。线上验收只做健康、资源、菜单和权限等只读检查，不在真实账号中创建模拟成绩。
