# 协助建档、无账号住宿与邮箱激活

实现已完成并通过源码审查；本文作为发布源打包前的证据快照，API 全量、最终浏览器矩阵及最终镜像加密恢复均已通过，NAS 发布仍待完成。生产代码基线为 `d06e57e`；截至 `3129677` 的后续变更仅涉及已审核的测试契约／完整检查脚本，未改变应用代码或业务权限。实际 NAS 发布及在线核验由主控另交付 `release-verification.md`；以下流程说明不是上线或原生验收证明。

## 业务流程

教练通过“我的建档申请”提交本人负责学员，领队／经理提交自己有效负责队伍的队员；兼任人员同时填写负责教练和队伍。本人姓名、校验正确的身份证、匹配的性别及出生日期、手机号、独立邮箱必填。未成年人至少填写一名成年监护人的姓名、身份证、手机号及关系；监护邮箱可不填，不要求先创建监护账号。

普通申请依次为待审核、退回（可修改后重新提交）、已通过，或主动撤回。普通提交必须由另一名有审核权限且范围覆盖的管理员审核；具有实际管理员／超管身份及审核能力者可显式使用“管理建档”。角色兼任不使普通申请自动批准。审批时重新校验当前角色、队伍／教练关系、目标版本和资料。旧版本、重复或并发决定不得创建第二份结果。

工作人员从人员中心的“我的建档申请”提交并查看状态；有权审核人员在审核队列处理，退回必须说明原因，通过可不填备注。已批准资料的姓名、身份证、激活邮箱及监护关系须由有相应人员管理权限者更正并保留原因，负责人不能直接覆盖。教练负责关系由有权管理员维护；队伍负责人及跨队转移仍走原超管入口。

待审核、退回和撤回资料不能入住或激活。已通过人员无需本人或监护人账号即可由有范围权限的行政、管理员／超管安排入住、确认入住、调房及退房，仍受房间性别、容量、日期及冲突规则约束。独立队员不伪建学员档案；兼任人员仅有一个人员身份。建档不会代报名、付款或产生邀请分成。

## 访问边界

“我的学员／队员”只显示当前负责范围的姓名、昵称、身份、授权归属及住宿摘要。负责人不能据此查看完整身份证、联系方式、监护资料、室友、住宿历史、财务或导出，不能修改房态。旧全局住房权限或遗留允许规则不是旁路。关系移交或角色撤销后，新请求会重新核验权限；同时拥有行政管理身份的人仍按实际管理范围办理。合法本人／家庭住房及室友查看保持原规则；仅有教练身份不等于家庭授权。

档案审核不代表监护人已验证、同意或获得家庭查看授权。已有账号的原始来源、停用／锁定状态、已验证联系方式、其他角色、队籍、住宿和邀请分成不会被新审批覆盖；既有未成年学员账号仍受原监护安全要求保护。

## 本人激活与错误处理

登录页选择“激活已有档案”，使用已获批档案的本人邮箱请求验证码，验证后设置 8–16 位、同时含 ASCII 大写／小写字母及数字的密码。完成后返回登录页，不自动登录。激活沿用原 `person_id`、监护关系、队籍及住宿历史，仅添加所需学员／队员角色。

仅支持邮箱 OTP，不发送短信，也不把手机号自动标记为已验证登录标识。验证码六位、十分钟有效；发送间隔和跨用途频率限制由服务端统一执行。页面只在内存中保留敏感草稿、密码和验证码，不将其写入 URL 或持久浏览器存储。切换账号、离开流程或权限失效会清理／隐藏相应内容。

请求受理提示不透露邮箱是否存在或资料状态。未收到邮件时先检查本人邮箱及垃圾邮件，稍后重试或联系管理员核实审批／邮件服务；不要连续猜测验证码。验证码失效、邮箱更正、资料变化、账号已存在／停用等情况应重新核实，不通过另建人员绕过冲突。重复提交或版本冲突时重新载入最新资料，确认后再操作。权限被撤销时联系管理员确认当前归属。
